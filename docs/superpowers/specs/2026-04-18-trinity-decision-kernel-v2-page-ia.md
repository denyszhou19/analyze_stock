# 三位一体页面信息架构确认稿

## 0. 目标

本确认稿用于约束后续页面改造：先确定信息分层、展示优先级和降级规则，再进入页面代码实现。

页面目标是让用户按以下顺序理解分析结果：

1. **现在怎么操作**：优先看 AI 最终一句话策略结论。
2. **为什么这样操作**：再看结构、时空、均线、量能、级别、执行六段规则链。
3. **底层怎么算出来**：最后看三类起点、原始结构、节点、场景路径等支撑细节。

页面不再把所有字段平铺展示；同一语义只出现一次，避免信息重复、卡片堆叠和关键结论被淹没。

## 1. 页面分区总览

| 页面区域 | 展示内容 | 为什么存在 | 必须降级的内容 |
| --- | --- | --- | --- |
| 综合判断区 | AI 最终一句话策略结论、AI 操作策略参考、主因、触发条件、风险条件、后端硬门控 | 让用户第一眼知道当前最值得参考的操作策略 | 原始 MACD 黑话、结构长解释、节点明细、历史分型 |
| 关键规则链 | 结构资格、MACD 时空、MA55 / MA233、量能确认、级别嵌套、执行计划 | 解释 AI 结论背后的确定性依据 | 大段解释文本、重复 badge、原始字段 dump |
| 支撑细节 / Debug | 三类起点、原始 classification、focus classification、node map、scenario paths、结构图与原始分型 | 给需要复盘和排错的人查看底层证据 | 不参与主结论的中间字段、长数组、低优先级说明 |

## 2. 综合判断区（最高优先级）

综合判断区是页面第一屏核心区域，主标题使用 **AI 最终一句话策略结论**。

### 2.1 主标题

来源：AI 报告契约中的 `summary.headline`。

示例：

```text
等待放量突破后轻仓试探
```

主标题不使用后端字段拼接，不使用旧版 `dailyData.macd.status` 分支文案。AI headline 是页面上的“操作策略参考”主表达。

### 2.2 左侧：AI 操作策略参考

展示 AI 摘要中的可执行信息：

- 操作动作：`summary.action`
- 当前倾向：`summary.bias`
- 主因：`summary.primary_reason`
- 触发条件：`summary.triggers`
- 风险条件：`summary.risks`
- 防线说明：`summary.guardrail`

展示要求：

- 主因必须短句化，不展示长篇分析。
- 触发条件和风险条件各最多显示 3 条，更多内容进入 AI Markdown 正文。
- 如果 AI 摘要缺失，综合判断区可以回退展示后端 `trinity_decision.conclusion`，但需要明确标记为“后端确定性结论”，不能伪装成 AI 结论。

### 2.3 右侧：后端硬门控

后端硬门控作为 AI 结论旁边的约束栏展示，不抢主标题。

展示字段：

- `periods.*.deterministic_decision.conclusion.action`
- `trade_qualification.trade_mode`
- `trade_qualification.position_permission`
- `trade_qualification.confidence`
- `structure.type`
- `structure.qualification`

展示原则：

- 如果后端 action 是 `wait` / `avoid`，页面必须清楚显示 AI 不能升级为 `buy` / `add`。
- 如果仓位权限是 `no_position`，页面必须清楚显示“禁止开仓 / 等待确认”。
- 如果仓位权限是 `light_probe`，页面只表达“轻仓试探”，不能展示成标准买入或加仓。

## 3. 关键规则链

关键规则链用于解释“为什么综合判断区得出这个策略”。它只展示每个规则模块的结论、状态和核心原因。

### 3.1 六段规则链

| 顺序 | 模块 | 核心展示 | 数据来源 |
| --- | --- | --- | --- |
| 1 | 结构资格 | 标准 / 延伸 / 通道 / 大平台 / 未完成 / 复杂；是否允许结构节点交易或边界交易 | `trinity_decision.structure` |
| 2 | MACD 时空 | 当前状态、方向偏置、结构是否匹配、背离策略 | `trinity_decision.spacetime` |
| 3 | 均线门控 | MA55 / MA233 支撑压制、是否允许多空方向 | `trinity_decision.moving_average` |
| 4 | 量能确认 | 突破 / 跌破 / 回踩是否获得量能支持，置信度升降 | `trinity_decision.volume_confirmation` |
| 5 | 级别嵌套 | 父子级别是否一致，是否降级为轻仓或等待 | `trinity_decision.level_nesting` |
| 6 | 执行计划 | 入场方式、触发条件、失效条件、仓位上限、风险标记 | `trinity_decision.execution` |

### 3.2 展示样式

每条规则链建议使用统一结构：

```text
规则名称
结论 badge
一句话原因
关键证据 1～2 条
```

示例：

```text
结构资格：延伸C / 边界交易
原因：平台延伸后停止标准节点编号，仅允许边界条件交易
证据：上沿 190.4；下沿 176.2
```

### 3.3 降级规则

以下内容不进入关键规则链主视图：

- 原始 `top_fractals` / `bottom_fractals` 列表。
- 完整 `strokes` 数组。
- `raw_classification.component_summary` 的长文本列表。
- 结构图渲染 payload。
- 重复表达同一结论的 badge。

这些内容统一放入支撑细节 / Debug 区。

## 4. 支撑细节 / Debug

支撑细节区面向复盘、排错和高级用户，默认不抢主阅读路径。

### 4.1 三类起点

展示：

- `background_origin`：宏观背景原点。
- `focus_origin`：当前聚焦结构起点。
- `execution_origin`：执行判断起点。

展示要求：

- 三类起点允许不同，必须展示各自语义。
- 如果宏观原点在窗口外，页面不能把窗口首点误当成宏观原点。
- `focus_origin` 和 `execution_origin` 不得混用。

### 4.2 结构解释明细

展示：

- `raw_classification`
- `focus_classification`
- `node_map`
- `boundaries`
- `scenario_paths`
- `explainability.evidence`

展示要求：

- 默认以折叠或次级卡片展示。
- 只在用户需要复盘时展开。
- 不与综合判断区和关键规则链重复表达相同结论。

### 4.3 原有页面内容迁移

旧页面中的以下内容需要重新分流：

| 旧内容 | 新位置 | 处理方式 |
| --- | --- | --- |
| AI 智能分析报告整段 Markdown | 综合判断区下方或详情展开 | 摘要先展示，正文降级为展开内容 |
| 核心结论三维度卡片 | 关键规则链的级别嵌套模块 | 保留结论，不再独立抢主视觉 |
| 多维度跨级别操作建议 | 关键规则链或支撑细节 | 与 `level_nesting` 去重后展示 |
| 每周期大块分析卡片 | 支撑细节 / 周期详情 | 作为详情区，不再压过综合判断 |
| 基于 MACD 状态硬编码的“操作策略参考” | 删除 | 改用 AI summary + 后端硬门控 |
| 关键价位卡片 | 综合判断区触发 / 风险条件的证据来源 | 仅保留关键价位，不重复生成操作建议 |

## 5. AI 与后端职责边界

### 5.1 AI 负责

- 把确定性结果整合为用户可读的一句话策略结论。
- 解释主因、触发条件、风险条件。
- 给出更自然的策略表达。

### 5.2 后端负责

- 给出不可突破的硬门控。
- 判断结构资格、时空状态、均线门控、量能确认、级别权限和交易资格。
- 输出触发条件、失效条件、仓位权限和风险标记。

### 5.3 页面负责

- 不重新推导交易结论。
- 不把 AI 结论升级到超过后端硬门控。
- 不把后端字段重复堆叠成多个相同语义的 badge。
- 按“综合判断 → 关键规则链 → 支撑细节”的顺序展示。

## 6. 页面空态与异常态

### 6.1 AI 摘要缺失

如果 AI 未返回合法摘要：

- 主标题回退为后端 `conclusion.action_label` + `trade_qualification.trade_mode`。
- 显示提示：“AI 摘要不可用，当前展示后端确定性结论。”
- AI Markdown 正文如果可用，仍可放入详情展开。

### 6.2 后端硬门控缺失

如果某周期缺少 `trinity_decision`：

- 不展示综合判断区的硬门控栏。
- 显示“确定性判定缺失，不能生成操作策略参考”。
- 页面不得只凭 AI Markdown 给出买卖建议。

### 6.3 规则链局部缺失

如果量能、级别嵌套或执行计划缺失：

- 对应模块显示“未提供”。
- 不隐藏整条规则链。
- 不用其它模块的结论替代缺失模块。

## 7. 信息重复控制

后续页面实现必须遵守：

- 同一个动作结论只在综合判断区主显示一次。
- 同一个等待原因只在综合判断区或规则链中出现一次，详情区可引用但不重复强调。
- badge 只承载短结论，例如 `等待`、`轻仓`、`边界交易`。
- 长解释只进入摘要文本或详情展开。
- Tooltip 只补充解释，不能承载必须先看到的核心信息。

## 8. 待用户确认的页面方向

本确认稿当前采用以下方向：

1. 综合判断区主标题展示 AI 最终一句话策略结论。
2. 后端硬门控放在综合判断区右侧，作为约束和证据，不抢主标题。
3. 关键规则链固定为六段：结构、时空、均线、量能、级别、执行。
4. 原始结构、节点、分型和 scenario paths 全部降级到支撑细节 / Debug。
5. 旧版基于 `dailyData.macd.status` 的硬编码“操作策略参考”在页面实现阶段删除。

用户确认本稿后，才能进入页面代码改造。
