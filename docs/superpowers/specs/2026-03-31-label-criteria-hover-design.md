# 结论标签 Hover 判定标准设计

## 背景

当前分析页已经能展示较多“结论型标签”，例如：

- `结构原型`
- `大级别背景`
- `当前段`
- `执行建议`
- `峰值后右侧结构`

但这些标签目前主要承担“给结论”的职责，用户看到的是：

- 这是什么标签
- 它当前显示为什么值

用户看不到的是：

- 为什么这样判
- 当前依据是什么
- 应该盯哪些关键阈值
- 什么情况下这个结论会被改判

这会让页面停留在“给答案”，而不是“让用户知其所以然”。

因此，本次补一份聚焦的 UI spec，为桌面端的结论型标签统一增加 `Hover 判定标准卡片`，让标签从“结果展示”升级为“结果 + 判定依据 + 失效条件”。

## 目标

- 为关键结论型标签提供统一的 Hover 判定标准卡片。
- 让用户在不离开当前页面的前提下，快速理解“为什么这样判”。
- 让卡片同时回答四个问题：
  - 这是什么结论
  - 为什么现在这样判
  - 哪些阈值最关键
  - 什么情况下会被改判
- 保持桌面端阅读舒适，不把标签 hover 做成难读的小 tooltip。

## 非目标

- 本次不改动结构拓扑图的画线逻辑。
- 本次不修改 `render_payload` 的几何层。
- 本次不重排拓扑图中的点位、线段、颜色和路径。
- 本次不覆盖移动端交互设计，先只做桌面端。
- 本次不要求新增所有后端结构判断算法，只定义标签解释交互和所需数据契约。

## 关键约束

### 1. 不影响拓扑画线

本次 hover 交互增强只作用于结论标签与说明层。

明确不触碰：

- `StructureTopologySvg` 的画线规则
- `render_payload.points / segments` 的几何含义
- 当前结构拓扑图中线段的坐标、粗细、颜色、虚实

如果后续结构语义模型升级影响到“当前段/next/live”的命名或编号，那属于后续结构模型任务，不属于本 spec。

### 2. 先做桌面端

本次只定义桌面端的 hover 交互，不要求移动端适配。

### 3. 只覆盖结论型标签

不是所有 badge 都应带 Hover 判定标准卡片。

只有会让用户追问“为什么这样判”的标签，才属于本 spec 的范围。

## 范围

### 1. 需要支持 Hover 判定标准卡片的标签

以下标签属于“结论型标签”，必须支持 Hover 判定标准卡片：

1. `结构原型`
   - 例如：`A五段式原型`、`B双平台原型`、`C平台原型`、`D三段式原型`
2. `大级别背景`
   - 例如：`偏多`、`偏空`、`整理`
3. `成熟度`
   - 例如：`候选`、`开展中`、`已确认`
4. `当前段`
   - 例如：`c3→live 下行`
5. `执行建议`
   - 例如：`等待`、`试仓`、`回抽确认`
6. `切片与峰值结论`
   - 例如：`峰值后右侧结构`、`山峰形态`、`山谷形态`

### 2. 不需要支持 Hover 判定标准卡片的标签

以下标签不属于“结论型标签”，不应使用同等级交互：

- `3个拐点`
- `中等置信度`
- `周线 / 日线 / 30分钟`
- `MA55`
- `MA233`
- 这类纯计数、纯维度、纯字段型标签

如果这些标签需要解释，应使用普通 tooltip 或静态说明，而不是判定标准卡片。

## 总体方案

采用统一的 `Hover 判定标准卡片` 方案。

每个结论型标签 hover 后，弹出一张更宽、可阅读的解释卡片，统一包含：

1. `结论标题`
2. `一句话定义`
3. `当前依据`
4. `关键阈值`
5. `改判条件`

这张卡片的定位不是“展示更多文字”，而是把标签背后的判定逻辑讲清楚。

## 交互规则

### 1. 触发方式

- 桌面端使用 `hover` 触发。
- 标签本身应使用 `cursor-help`。
- 鼠标移入标签后显示判定标准卡片。
- 鼠标从标签移动到卡片区域时，卡片不得立刻消失。

### 2. 收起规则

- 当鼠标同时离开标签和卡片区域后，延迟 `120ms ~ 180ms` 收起。
- 用短延迟避免闪烁和误触。

### 3. 同屏互斥

- 同一时刻最多只允许一个 Hover 判定标准卡片展开。
- 鼠标移动到另一个标签时，旧卡片收起，新卡片展开。
- 不允许多个卡片叠加遮挡。

### 4. 定位规则

- 默认在标签下方靠左展开。
- 若右侧空间不足，则向左展开。
- 若下方空间不足，则翻转到上方。
- 卡片必须尽量完整显示在视口内。

### 5. 尺寸规则

- 宽度建议 `320px ~ 380px`
- 不得窄成普通 tooltip 风格
- 最大高度受视口限制，超出时内部滚动
- 目标是“短阅读卡片”，不是 modal

### 6. 视觉层级

- 比普通 tooltip 信息更完整
- 比 popover 更轻
- 建议使用：
  - 清晰边框
  - 轻阴影
  - 标题 + 分区
  - 更舒适的行高

不建议：

- 纯黑极小 tooltip
- 过重的弹窗感
- 大段连续正文

## 内容结构

所有 Hover 判定标准卡片共用同一套骨架：

1. `结论标题`
2. `标签类型`
3. `一句话定义`
4. `当前依据`
5. `关键阈值`
6. `改判条件`

### 1. 结论标题

展示当前标签的名称。

例如：

- `C平台原型`
- `背景偏多`
- `c3→live 下行`
- `等待`

### 2. 标签类型

用于帮助用户知道“这是哪一类结论”，例如：

- `结构原型`
- `大级别背景`
- `当前段`
- `执行建议`

它是辅助信息，视觉权重低于标题。

### 3. 一句话定义

解决“这是什么”的问题。

要求：

- 不超过两行
- 偏概念解释
- 不重复标题

例如：

- `C平台原型：当前走势存在明显重叠区间，更像单平台整理，不代表方向已经确认。`
- `背景偏多：更大级别骨架仍偏向多头，当前回撤暂未破坏主背景。`

### 4. 当前依据

解决“为什么现在这样判”的问题。

要求：

- 使用 `2 ~ 4` 条短 bullet
- 尽量使用当前这只股票当前周期的真实证据
- 不允许空洞描述

例如：

- `价格仍在 MA55 / MA233 上方`
- `MA55 仍高于 MA233`
- `c1-c2-c3 已形成来回切换`
- `高低点进入重叠区间`

### 5. 关键阈值

解决“用户接下来最该看哪里”的问题。

允许展示：

- 关键价位
- 关键均线
- 关键确认点

例如：

- `上沿：181.99 / 209.88`
- `下沿：141.10`
- `确认点：等待 c4`

要求：

- 最多 `3` 条
- 必须是行动上有意义的阈值

### 6. 改判条件

解决“什么情况下这个结论不再成立”的问题。

例如：

- `有效上破平台上沿：可升级为推进结构`
- `有效跌破平台下沿：平台破坏，转弱`
- `关键低点被破坏：背景偏多需重算`

要求：

- 最多 `2` 条
- 必须具有明确方向性
- 不能写成模糊废话

## 统一数据契约

前端不应临时拼接不同标签的 Hover 内容。

建议统一由后端或视图模型层产出：

```ts
type LabelCriteriaCard = {
  key: string;
  title: string;
  category: 'archetype' | 'background' | 'maturity' | 'current_leg' | 'execution' | 'focus_mode';
  summary: string;
  definition: string;
  evidence: string[];
  thresholds: Array<{
    label: string;
    value: string;
  }>;
  rejudge_conditions: string[];
  confidence?: 'low' | 'medium' | 'high';
};
```

说明：

- `title`
  标签标题
- `category`
  标签分类，用于 UI 次标题、图标、配色
- `summary`
  用于标签自身或简要说明区
- `definition`
  一句话定义
- `evidence`
  当前依据列表
- `thresholds`
  关键阈值
- `rejudge_conditions`
  改判条件
- `confidence`
  可选，用于辅助视觉，不作为主文案

## 各类标签的字段映射

### 1. 结构原型标签

例如：

- `A五段式原型`
- `C平台原型`
- `D三段式原型`

建议来源：

- `focus_structure.archetype_label`
- `focus_structure.maturity`
- `focus_structure.display_reason`
- `scenario_paths`

卡片内容应体现：

- 这个原型本质上是什么
- 为什么当前更像它
- 它现在处于哪个成熟度
- 上破/下破后如何升级或失效

### 2. 大级别背景标签

例如：

- `偏多`
- `偏空`
- `整理`

建议来源：

- `macro_background.label`
- `macro_background.basis`
- 均线与峰谷骨架摘要

卡片内容应体现：

- 这是背景结论，不等于当前最后一段方向
- 当前为什么判为偏多/偏空/整理
- 哪些均线或关键高低点是背景阈值
- 背景什么时候需要重算

### 3. 成熟度标签

例如：

- `候选`
- `开展中`
- `已确认`

建议来源：

- `focus_structure.maturity`
- 关键点数量和确认状态

卡片内容应体现：

- 这个成熟度的定义
- 当前为什么还只是候选/开展中
- 还差什么确认才升级
- 什么情况下会直接失效

### 4. 当前段标签

例如：

- `c3→live 下行`
- `a3→live 上行`

建议来源：

- `current_leg`
- `next_confirmation`

卡片内容应体现：

- 这是 forming 尾段，不等于新编号点
- 最后确认点是谁
- 当前方向为什么这样判
- 要等什么确认才升级为正式段

### 5. 执行建议标签

例如：

- `等待`
- `试仓`
- `回抽确认`

建议来源：

- `execution_phase`
- `execution`

卡片内容应体现：

- 当前这条建议是什么意思
- 为什么现在是这个建议
- 什么触发后可以改变建议
- 失效后应如何理解

### 6. 峰值/谷值切片标签

例如：

- `峰值后右侧结构`
- `山峰形态`
- `山谷形态`

建议来源：

- `focus_structure.focus_mode`
- `peak_analysis`

卡片内容应体现：

- 当前为何采用峰值/谷值右侧切片
- 左右两侧各自是什么结构
- 为什么当前战术焦点在右侧
- 这种切片最容易被误读的点是什么

## 示例

### 1. `C平台原型`

- 标题：`C平台原型`
- 标签类型：`结构原型`
- 定义：`当前走势存在明显重叠区间，更像单平台整理，不代表方向已经确认。`
- 当前依据：
  - `c1-c2-c3 已形成来回切换`
  - `高低点进入同一重叠区间`
  - `当前尾段仍未完成确认`
- 关键阈值：
  - `上沿：181.99 / 209.88`
  - `下沿：141.10`
  - `确认点：等待 c4`
- 改判条件：
  - `有效上破平台上沿：可升级为推进结构`
  - `有效跌破平台下沿：平台破坏转弱`

### 2. `背景偏多`

- 标题：`背景偏多`
- 标签类型：`大级别背景`
- 定义：`更大级别骨架仍偏向多头，当前回撤暂未破坏主背景。`
- 当前依据：
  - `价格仍在 MA55 / MA233 上方`
  - `MA55 高于 MA233`
  - `关键低点尚未系统性下破`
- 关键阈值：
  - `MA55：118.57`
  - `MA233：85.61`
  - `关键低点：141.10`
- 改判条件：
  - `跌破关键低点且均线关系明显转弱：背景偏多需重算`

### 3. `c3→live 下行`

- 标题：`c3→live 下行`
- 标签类型：`当前段`
- 定义：`从最后确认拐点 c3 出发的实时下行尾段，尚未确认成新拐点。`
- 当前依据：
  - `最后确认点为 c3`
  - `最新价仍在 c3 下方`
  - `当前终点仍是 live`
- 关键阈值：
  - `确认点：等待 c4`
  - `回抽高点：181.99`
- 改判条件：
  - `出现新的确认底分型：live 升级为 c4`

## 实现建议

### 1. 组件层

建议新增通用组件：

- `CriteriaHoverCard`
  负责卡片框体与交互
- `CriteriaBadge`
  负责 badge 与 hover 卡片绑定

### 2. 视图模型层

建议新增：

- `buildLabelCriteriaCards(...)`

负责从：

- `structure`
- `execution_phase`
- `execution`
- `peak_analysis`
- `macro_background / focus_structure / current_leg`

映射出前端可直接消费的 `LabelCriteriaCard[]`

### 3. 首期落地顺序

建议先覆盖以下高价值标签：

1. `结构原型`
2. `大级别背景`
3. `当前段`
4. `执行建议`

第二批再补：

5. `成熟度`
6. `峰值/谷值切片结论`

## 验收标准

### 1. 交互验收

- 结论型标签 hover 后，能稳定弹出判定标准卡片
- 鼠标从标签移入卡片时不闪烁
- 同一时刻最多一个卡片展开
- 卡片不会超出视口主要可读区域

### 2. 内容验收

每张卡片必须同时具备：

- 一句话定义
- 当前依据
- 关键阈值
- 改判条件

若缺失其中任意核心区块，则视为不合格。

### 3. 范围验收

- 只有结论型标签使用 Hover 判定标准卡片
- 计数类与纯字段类标签不应误用这套交互

### 4. 不侵入拓扑画线验收

本次实现后，以下内容不应发生改变：

- 结构拓扑图的线段坐标
- `render_payload` 的几何层
- 拓扑图中的画线逻辑

允许变化的仅限于：

- 标签交互
- 标签 hover 卡片
- 相关视图模型与解释文案
