# 三位一体分析页综合判断与信号展示设计

## 0. 背景

`2026-04-19-trinity-global-analysis-page-ux-upgrade-design.md` 与 `2026-04-20-trinity-interpretability-language-design.md` 已经完成了分析页骨架重组与表达层增强，页面目前已经具备：

- 页面级综合结论
- 交易周期总线
- 三位一体规则链
- 周期详情
- AI 分析区

但在真实使用中，页面仍然存在一组更深层的表达问题：

1. 页面当前容易偏成“结构页”，而不是“三位一体综合判断页”。
2. `等待确认`、`存在约束`、`等待触发` 这类表述过于抽象，用户不知道现在到底能做什么。
3. 系统已经有不少信号与判断，但前端仍存在标签裁剪、摘要截断、主信息缺失的问题。
4. 页面和 AI 目前仍受旧展示槽位约束，难以表达“候选结构”“先手点”“确认点”“失效点”这类交易辅助信息。
5. 部分关键强信号，例如 `零轴金叉 / 零轴死叉`、`顶底背离`、完整 `突破/跌破` 家族，没有稳定进入主视区。

因此，本设计的目标不是继续重做页面骨架，而是在保留现有大区块位置的前提下，统一：

- 页面主信息顺序
- 信号标签项目标准
- 主内容与 hover 的职责边界
- 前后端字段合同
- AI 分析区的表达上限

## 1. 设计结论

本次采用的方案是：

> 保留现有页面大区块位置不变，但将每个核心区块统一改造成“当前综合判断 -> 三位一体拆解 -> 执行预案”的表达顺序。

这意味着：

- `AI 分析区` 位置不变，但表达顺序升级
- `交易周期总线` 仍保留三张组合卡，但主内容改成决策语言
- `三位一体规则链` 仍保留六张卡，但每张卡先回答“当前是在放行、限制还是观察”
- `周期详情` 仍保留当前结构与证据区，但顶部新增单周期结论头

本次不采用“彻底重构整个页面布局”的方案，也不采用“只改文案、不改信息顺序”的最小方案。

## 2. 目标与非目标

### 2.1 目标

本次设计目标有七个：

1. 明确分析页不是“结构页”，而是“三位一体综合判断页”。
2. 让页面先回答“现在能不能做、为什么、怎么做”，再展开证据。
3. 允许 `live` 段参与“候选结构”判断，用于交易预判。
4. 让系统在结构未完全确认前，也能给出 `先手点 / 确认点 / 失效点`。
5. 把信号标签统一为项目标准，并恢复所有已命中标签的可见性。
6. 提升 AI 分析区表达上限，使其不再被旧页面槽位限制。
7. 明确哪些工作可以先靠前端落地，哪些必须后端补合同。

### 2.2 非目标

本次设计明确不做以下事情：

1. 不重做整个分析页的大布局与区块顺序。
2. 不把所有逻辑解释都塞进卡面主内容。
3. 不新增具体交易算法，也不直接修改结构算法本身。
4. 不要求所有字段都在第一阶段由后端一次性补齐。

## 3. 核心原则

### 3.1 这是三位一体综合判断页，不是结构页

新的页面总原则是：

> 时空决定能不能做，结构决定现在在走什么，执行决定现在怎么做。

因此页面和 AI 都不能先报结构名，再补一点别的信息。正确顺序是：

1. `当前综合判断`
2. `三位一体拆解`
3. `执行预案`

### 3.2 正式结构负责诚实，候选结构负责交易

页面必须同时容纳两层结构结论：

- `正式结构`
  只按确认拐点定型，负责回答“现在正式能叫 A/B/C/D 了吗”
- `候选结构`
  允许 `live` 段参与判断，负责回答“当前正在朝什么结构演变”

页面允许出现：

- `D 候选`
- `A 延续候选`
- `C 候选`

但不能把这些候选直接伪装成正式结构。

### 3.3 不能等结构走完才给交易辅助

系统是交易辅助系统，不是事后复盘系统。

因此只给“正式确认后结论”是不够的。页面必须在候选结构阶段提前给出：

- `先手点`
- `确认点`
- `失效点`
- `当前适合的仓位动作`

### 3.4 hover 只能补充解释，不能承载核心信息

hover 的职责是解释，不是补课。

禁止把以下内容藏进 hover：

- 当前综合判断
- 候选结构
- 先手点 / 确认点 / 失效点
- 已命中的核心标签
- 当前适合动作

hover 只能补：

- 这句话是什么意思
- 为什么这么判断
- 当前限制是什么
- 现在盯什么
- 满足后怎么做
- 什么情况取消

### 3.5 标签全部展示，优先级只决定顺序

只要是当前已命中的相关标签，就必须展示。

页面统一采用：

- 全部标签按顺序混排
- 不分组
- 不做数量截断
- 不做 `+N` 折叠
- 优先级只决定从左到右顺序，不决定是否显示

## 4. 统一判断模型

### 4.1 当前综合判断三档

页面主结论统一落在三档：

- `严格等待`
- `候选可试`
- `确认执行`

这三档不是结构翻译，而是三位一体融合结论，必须综合：

- 时空状态
- 时空强事件
- 正式结构
- 候选结构
- 均线门槛
- 量能确认
- 突破/跌破家族
- 顶底背离
- 指标共振
- 父子级别关系

### 4.2 父子关系统一语言

页面主语言统一保留以下两句：

- `父级强冲突，子级逆父级`
- `父级支持，子级顺父级`

交易含义只放 hover 和解释层展开，不再在主内容里重复造句。

### 4.3 候选结构规则

本次设计明确采用以下规则：

> `live` 段可以参与“候选结构”判断；页面可以说 `D 候选 / A 延续候选`，但正式结构仍等确认拐点后再定。

### 4.4 执行分层

执行信息统一拆成三层：

- `严格等待`
  父级明确不允许，或当前信号仍混乱、冲突大于支持
- `候选可试`
  候选结构已出现，但尚未形成完整确认，允许轻仓试
- `确认执行`
  候选与其他关键门槛已形成确认，可按计划加仓或执行

## 5. 信号标签项目标准

### 5.1 基础标准

全项目标签统一采用：

```text
类别｜结果
```

例如：

- `时空｜中偏强`
- `时空｜零轴金叉`
- `背离｜顶背离`
- `突破/跌破｜回抽突破确认`
- `量能｜突破量弱`
- `均线｜MA55支撑`
- `结构｜C单平台`

标签颜色继续复用现有共享语义：

- `bullish`
- `bearish`
- `warning`
- `neutral`

该标准升级为项目标准，不再允许业务组件自行发明 badge 语言和颜色。

### 5.2 标签展示规则

标签展示统一采用：

- 全部标签按顺序混排
- 自动换行
- 不分组
- 不截断
- 不折叠

推荐排序为：

1. 时空状态
2. 时空事件
3. 背离
4. 突破/跌破
5. 量能
6. 均线
7. 结构
8. 级别
9. 执行
10. 共振

### 5.3 时空信号标准

时空必须同时保留两类标签：

- `时空状态标签`
  例如 `时空｜中偏强`、`时空｜极弱`
- `时空事件标签`
  例如 `时空｜零轴金叉`、`时空｜零轴死叉`

两者并存，不互相替代。

### 5.4 零轴强信号标准

根据 `docs/pdf/三位一体结构深究.pdf`，`零轴金叉 / 零轴死叉（如果形成）` 属于最强时空信号。

因此：

- `零轴金叉 / 零轴死叉` 一旦形成，必须进入主标签首位序列
- 它们不是普通零轴事件，而是高优先级强信号
- `二次金叉 / 二次死叉` 作为再次确认，进入次级展示或解释层

### 5.5 顶底背离标准

`顶背离 / 底背离` 必须恢复为一等标签。

只要当前周期存在明确背离，就必须进入标签主视区，不能再因为摘要优先级被挤掉。

### 5.6 突破/跌破家族标准

页面设计必须覆盖当前系统已实现的完整家族，而不能只围绕少数例子设计。

完整家族至少包括：

- `假突破 / 假跌破`
- `有效突破 / 有效跌破`
- `慢速突破 / 慢速跌破`
- `回抽突破 / 回抽跌破`
- `反向突破 / 反向跌破`
- `普通突破 / 普通跌破`
- `无突破`

同一时刻只应有一个“主突破/跌破事件标签”，但完整事实仍需通过排序与 hover 呈现。

### 5.7 指标共振标准

新增统一的 `共振` 语义，用于表达多技术信号是否一致。

推荐展示语言：

- `共振｜多信号共振`
- `共振｜弱共振`
- `共振｜信号冲突`

该结论必须综合：

- 时空
- 结构
- 均线
- 量能
- 突破/跌破
- 背离
- 父子级别关系

## 6. 四个区块的显示合同

### 6.1 AI 分析区

AI 分析区位置不变，但主内容顺序必须升级为：

1. `当前综合判断`
2. `父子关系`
3. `时空怎么看`
4. `结构怎么看`
5. `现在怎么做`

AI 主内容必须直接包含：

- 当前综合判断
- 父级支持/冲突
- 时空状态与强事件
- 正式结构与候选结构
- 先手点 / 确认点 / 失效点

AI 区的 hover 只补：

- 某个术语是什么意思
- 某个标签为什么成立
- 证据来源

### 6.2 交易周期总线

交易周期总线继续保留原有三张组合卡与四个说明块，但主内容职责改为：

- `当前综合判断`
- `父子关系`
- `一句三位一体摘要`
- `一句动作建议`
- `全部相关标签按顺序混排`
- `四个说明块`
  - `父级约束`
  - `触发级别`
  - `适合动作`
  - `主要风险`

这四个说明块必须可直接读懂，不允许只抛术语。

其中：

- `父级约束` 要明确卡在时空、结构、量能、均线还是级别权限
- `触发级别` 要明确哪个级别、盯什么动作
- `适合动作` 要直接落成交易动作
- `主要风险` 要优先写失效条件

### 6.3 三位一体规则链

规则链继续保留六张卡，但每张卡必须先回答：

- 当前是在 `限制`
- 还是 `放行`
- 还是 `观察`

每张卡的主内容固定包含：

- 规则名
- 当前状态
- 一句解释
- 一句交易含义
- 该卡所有相关标签按顺序混排

六张卡职责分别为：

- `MACD 时空卡`
  - 时空状态
  - 零轴强事件
  - 背离
  - 时空共振/冲突
- `结构卡`
  - 正式结构
  - 候选结构
  - 当前进行段
- `55 / 233 线关系卡`
  - 支撑/压制
  - 突破/跌破家族
- `量能卡`
  - 放量确认
  - 缩量回踩
  - 量弱
  - 过热
- `级别卡`
  - 父子关系
- `执行卡`
  - 先手点
  - 确认点
  - 失效点

### 6.4 周期详情

周期详情是单周期最完整的落地层，顶部必须新增单周期结论头，固定显示：

- `当前综合判断`
- `父子关系`
- `全部相关标签按顺序混排`
- `时空摘要`
- `结构摘要`
- `执行摘要`

其中：

- `时空摘要`
  必须直接包含当前强弱、零轴金叉/死叉是否形成、背离是否存在、共振是否支持
- `结构摘要`
  必须直接包含正式结构与候选结构
- `执行摘要`
  必须直接包含先手点、确认点、失效点

拓扑图、结构解释块、信号标签全集与证据区继续保留在下方。

## 7. 主内容与 hover 的职责边界

### 7.1 主内容必须承担的信息

所有区块主内容都必须直接承载：

- 当前综合判断
- 父子关系
- 已命中的标签
- 正式结构 / 候选结构
- 先手点 / 确认点 / 失效点
- 当前适合动作

### 7.2 hover 的统一合同

任何支持 hover 的字段，都统一只解释：

1. 这句话是什么意思
2. 为什么这么判断
3. 当前限制是什么
4. 现在盯什么
5. 满足后怎么做
6. 什么情况取消

### 7.3 明确禁止

禁止以下做法：

- 把“当前综合判断”放进 hover
- 把“候选结构”放进 hover
- 把“先手点 / 确认点 / 失效点”放进 hover
- 把标签裁剪后再让 hover 补缺
- 主内容只抛术语，把真正可执行信息都藏到 hover 里

## 8. 前后端职责划分

### 8.1 前端第一阶段可直接落地的内容

现有 payload 已经足够支持第一阶段展示升级，主要包括：

- 取消标签裁剪，恢复全展示
- 恢复背离标签可见性
- 稳定展示完整突破/跌破家族标签
- 在总线、规则链、周期详情顶部按新顺序组织已有字段
- 将父子级别关系翻译为统一中文主语句

### 8.2 前端可暂时推导，但不建议长期猜测的内容

前端可以临时推导第一版，但长期不应自行猜测：

- 当前综合判断三档
- 当前适合动作

这些结论最终应由后端显式输出，以避免前后端口径漂移。

### 8.3 必须由后端补充的字段

以下语义不应长期依赖前端从字符串或散落字段中推断，必须形成稳定合同：

1. `综合判断字段`
   - `judgment`
   - `label`
   - `headline`
   - `reason`
   - `action_hint`
   - `confidence`

2. `等待类型字段`
   - `wait_type`
   - `label`
   - `current_focus`
   - `upgrade_condition`
   - `cancel_condition`
   - `reason`

3. `候选结构字段`
   - `candidate_type`
   - `candidate_label`
   - `stage`
   - `direction`
   - `reason`
   - `upgrade_condition`
   - `downgrade_condition`
   - `invalidation`

4. `时空强事件字段`
   - `event_type`
   - `label`
   - `strength`
   - `formed`
   - `reason`
   - `trade_meaning`
   - `failure_risk`

5. `指标共振字段`
   - `status`
   - `label`
   - `aligned_signals`
   - `conflicting_signals`
   - `reason`
   - `impact_on_judgment`

6. `父子关系展示字段`
   - `relation`
   - `label`
   - `reason`
   - `trade_impact`

7. `执行预案展示字段`
   - `probe_entry`
   - `confirm_entry`
   - `invalidation`
   - `position_action`
   - `position_note`
   - `current_best_focus`

8. `突破/跌破展示分级字段`
   - `family`
   - `label`
   - `direction`
   - `trade_impact`
   - `reason`

推荐优先在 `TrinityDecision` 与 `PeriodAnalysisData.breakthrough` 上自然扩展，而不是新起一套独立 `ui_payload`。

## 9. 分阶段落地建议

### 9.1 第一阶段：前端展示重组

第一阶段目标是先解决“看不见、看不全、看不懂”的问题。

实施重点：

- 标签全展示混排
- 背离恢复主视区
- 突破/跌破家族完整进入主视区
- 总线 / 规则链 / 周期详情改成新顺序
- AI 分析区改成新表达顺序

### 9.2 第二阶段：后端合同补齐

第二阶段目标是让页面与 AI 不再依赖前端推断。

实施重点：

- 候选结构合同
- 零轴强事件合同
- 指标共振合同
- 当前综合判断合同
- 等待类型合同
- 执行预案展示合同

### 9.3 第三阶段：AI 分析升级

当第二阶段合同齐备后，AI 分析区应升级为真正的三位一体综合表达：

1. 当前综合判断
2. 时空怎么看
3. 结构怎么看
4. 现在怎么做

届时 AI 不再只是复述旧 `headline / triggers / risks / guardrail`。

## 10. 验收标准

本设计完成后的页面，应满足以下验收条件：

1. 用户进入分析页后，先看到的是“现在能不能做、为什么、怎么做”，而不是先看到结构名。
2. 任一核心区块都不再只说“等待确认”，而能明确说明在等什么。
3. 页面允许稳定表达 `D 候选 / A 延续候选 / C 候选`，且不与正式结构混淆。
4. `零轴金叉 / 零轴死叉`、`顶底背离`、完整 `突破/跌破` 家族能稳定进入主视区。
5. 所有已命中标签都能看见，不再被截断或挤掉。
6. hover 只负责解释，不再承担用户必须先看到的核心信息。
7. AI 分析区仍在原位置，但表达能力显著升级。

## 11. 风险与边界

本设计的主要风险不在页面，而在字段合同不完整时，前端容易继续“代替后端做判断”。

因此实现时必须坚持以下边界：

- 第一阶段可以先用前端重组展示，但不能长期把交易结论建立在字符串猜测上
- 第二阶段必须补齐候选结构、零轴强事件、共振、等待类型等显式字段
- 页面升级不应反过来扭曲现有交易算法语义

一句话总结：

> 页面要先升级为“会说人话的三位一体综合判断页”，后端再逐步把这些人话背后的判断合同显式化。
