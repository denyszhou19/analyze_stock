# 三位一体 AI 综合判断第三阶段设计

## 0. 背景

`2026-04-21-trinity-analysis-page-judgment-display-design.md` 与第一阶段实现，已经完成了分析页的信息重组：

- 页面先表达当前综合判断
- 交易周期总线、规则链、周期详情、AI 区统一了信息顺序
- 标签恢复为主视可见，不再被过度隐藏

`2026-04-22-trinity-judgment-contract-phase2-design.md` 与第二阶段实现，则已经完成了判断合同补齐：

- 候选结构
- 等待状态
- 零轴强信号
- 共振判断
- 背离权重
- 综合判断
- 执行预案

这些字段已经成为正式后端 payload 的一部分，并进入 `periods.*.deterministic_decision`。

但当前 AI 综合判断链路仍然停留在旧合同阶段：

1. AI route 虽然已经拥有三位一体策略上下文与完整决策 payload，但输出契约仍然只强制 `headline / action / bias / primary_reason / triggers / risks / guardrail`。
2. parser 只解析旧摘要字段，无法把第二阶段新增判断语义接到 AI 摘要层。
3. 页面 AI 区虽然已经按新的顺序展示，但很多核心摘要仍然来自后端 fallback，而不是 AI 自己结构化输出。
4. AI 已经“知道”更多三位一体上下文，但这些上下文还没有被稳定释放到页面主结论区。

因此，第三阶段的重点不是继续补后端判断合同，而是：

- 升级 AI 输出合同
- 升级 route prompt 与 parser
- 让 AI 在不破坏后端正式边界的前提下，输出更完整的三位一体摘要与明细解释

## 1. 设计结论

第三阶段采用以下方案：

> 保留 `JSON 摘要 + Markdown 正文` 的双层输出，同时扩展 JSON 摘要字段，让 AI 正式对齐第二阶段判断合同；Markdown 负责承载更多明细解释。

同时明确 AI 与后端的关系：

> 后端负责当前正式边界，AI 负责条件升级预案与判断疑点提示。

这意味着：

- 不废弃现有 JSON 摘要模式
- 不把 AI 改造成纯结构化对象接口
- 不允许 AI 直接推翻后端当前正式动作
- 允许 AI 给出“若满足 X，则可升级为 Y”的条件升级预案
- 允许 AI 指出后端结论与输入信号之间的明显张力或疑点

## 2. 目标与非目标

### 2.1 目标

第三阶段目标有七个：

1. 保留现有 `JSON 摘要 + Markdown 正文` 的输出结构，兼容现有交互。
2. 让 AI 摘要正式吃到第二阶段新增判断语义，而不再只复述旧的 7 个摘要字段。
3. 让页面 AI 区的主结论真正来自 AI 的结构化摘要，而不是大量依赖后端 fallback。
4. 让 Markdown 正文按新的三位一体顺序输出更多明细信息。
5. 允许 AI 在不越过正式动作边界的前提下，给出条件升级预案。
6. 允许 AI 指出后端结论与输入信号之间的疑点或矛盾。
7. 保持旧解析链兼容，避免第三阶段一次性打爆现有页面与测试。

### 2.2 非目标

第三阶段明确不做：

1. 不再新增第二阶段那类后端判断合同字段。
2. 不重做分析页整体布局。
3. 不把 Markdown 正文完全拆解为前端结构化 UI。
4. 不允许 AI 直接改写后端 `wait / avoid / light_probe / t_trade_only` 等正式动作边界。
5. 不重新定义整套三位一体策略知识库。

## 3. 当前问题定位

### 3.1 AI 实际上已经有三位一体上下文

当前 AI route 已经拥有两层上下文：

1. **策略知识上下文**
   - route 中写死了完整的三位一体策略系统提示词
   - 包括时空状态、ABCD 结构、背离、均线物理性质、突破/跌破、级别嵌套、做 T 与仓位规则

2. **当前标的决策上下文**
   - `buildAiDecisionPayload()` 会把完整的决策结论 JSON 喂给 AI
   - 包括 `periods.*.deterministic_decision`
   - 第二阶段新增字段也已经进入 payload

所以第三阶段的瓶颈不是“AI 没有上下文”，而是“AI 输出合同没有释放这些上下文”。

### 3.2 当前真正进入主消费链的仍是旧摘要 7 字段

当前 parser 与页面主结论区稳定消费的仍然只有：

- `headline`
- `action`
- `bias`
- `primary_reason`
- `triggers`
- `risks`
- `guardrail`

这导致：

- AI 虽然知道候选结构、等待状态、执行预案等新语义
- 但页面主结论区还不能正式消费这些结果
- 很多“三位一体摘要”仍由后端 deterministic fallback 负责生成

### 3.3 当前最稳定的 AI 约束仍是“动作不能越权”

当前 route 已经明确要求：

- AI 必须服从 `periods.*.deterministic_decision.conclusion.action`
- 必须服从 `trade_qualification`
- 必须服从 `position_permission`

这条约束是正确的，但如果只剩这一条，AI 就会继续停留在：

- 会解释
- 但不会充分表达条件升级预案
- 也不会明确指出后端判断中的疑点

## 4. AI 输出合同升级

### 4.1 继续保留双层输出

第三阶段继续保留：

- `JSON 摘要`
- `Markdown 正文`

原因：

1. `JSON 摘要` 适合页面主结论稳定消费。
2. `Markdown 正文` 适合承载你明确需要的更多明细信息。
3. 若直接改成“纯结构化 JSON 为主”，第三阶段范围会过大。

### 4.2 JSON 摘要保留兼容字段

以下旧字段继续保留，并保持必填：

- `headline`
- `action`
- `bias`
- `primary_reason`
- `triggers`
- `risks`
- `guardrail`

原因：

- 兼容现有 parser
- 兼容现有 AI 区 fallback 逻辑
- 保证第三阶段可以渐进接管

### 4.3 JSON 摘要新增增强字段

在旧字段基础上，新增以下增强字段：

- `judgment`
  - 当前综合判断
  - 只允许：`严格等待 / 候选可试 / 确认执行`

- `critical_reason`
  - 当前最关键原因
  - 用一句中文说清为什么当前是这个判断

- `spacetime_summary`
  - 一句话总结时空状态、父子级别关系、零轴强信号与时空门控

- `structure_summary`
  - 一句话总结正式结构与候选结构当前状态

- `execution_summary`
  - 一句话总结当前动作建议与执行层含义

- `candidate_structure`
  - 轻量摘要对象，仅包含：
    - `label`
    - `current_leg`
    - `upgrade_condition`
    - `invalidation`

- `wait_state`
  - 轻量摘要对象，仅包含：
    - `label`
    - `current_block`
    - `next_action`

- `judgment_warning`
  - 可选
  - 用于表达“后端判断疑点 / 输入信号存在张力 / 当前存在保守降级”

设计原则：

- JSON 摘要只放页面主结论真正会直接消费的内容
- 不把完整推理细节和多层因果链强塞进 JSON

### 4.4 Markdown 正文承载详细解读

Markdown 正文固定按以下顺序组织：

1. 当前综合判断
2. 时空怎么看
3. 结构怎么看
4. 现在怎么做
5. 风险与应对

Markdown 正文重点承载：

- 候选结构为何成立
- 当前卡点与下一确认动作
- 条件升级预案
- 先手点 / 确认点 / 失效点
- 父子级别关系
- 零轴强信号、背离、共振的解释
- 多周期之间的因果链
- 若出现矛盾，矛盾来自哪里

一句话总结：

> JSON 摘要负责“能稳定展示”，Markdown 正文负责“能充分解释”。

## 5. AI 与后端的关系边界

### 5.1 后端负责当前正式边界

后端当前输出的正式动作边界仍然是最高优先级：

- `periods.*.deterministic_decision.conclusion.action`
- `trade_qualification`
- `position_permission`

第三阶段不允许 AI 把这些正式边界直接改写成更激进的正式动作。

### 5.2 AI 采用“条件性越权”模式

第三阶段采用如下模式：

> AI 不直接推翻后端当前正式动作，但可以明确给出条件升级预案。

允许的表达示例：

- `当前后端正式判断仍为等待`
- `若 30 分钟完成回抽确认，则可升级为候选可试`
- `若再出现放量突破并站稳，则可升级为确认执行`

不允许的表达示例：

- 后端当前是 `wait / avoid`，AI 却直接写成“现在立即买入 / 现在立即加仓”

### 5.3 AI 允许指出后端疑点

当 AI 发现以下情况时，允许显式指出：

1. 后端正式判断与输入信号存在明显张力
2. 候选结构、零轴强信号、突破/回抽、背离、共振之间存在明显冲突
3. 后端结论明显偏保守，且与当前判断链不完全一致

这类提示属于：

- `判断疑点`
- `保守降级提醒`
- `输入信号与正式结论存在张力`

但 AI 即使指出疑点，也仍需遵守：

- 不能直接改写后端当前正式动作
- 只能通过“条件升级预案”表达下一步可能升级路径

一句话总结：

> 后端负责当前拍板，AI 负责条件升级预案与疑点提示。

## 6. route / parser / 页面消费链改造

### 6.1 route：升级 AI 输出任务定义

`src/app/api/stock/ai-analysis/route.ts` 需要完成三件事：

1. 保留现有三位一体策略系统提示词与后端硬边界约束。
2. 把第二阶段新增字段正式提升为 AI 摘要与正文的必读输入。
3. 重写输出契约，明确：
   - JSON 摘要保留旧字段并新增增强字段
   - Markdown 正文按新的三位一体顺序输出
   - 允许条件升级预案
   - 允许判断疑点提示

### 6.2 parser：从旧 7 字段升级为“旧字段兼容 + 新字段可选解析”

`src/lib/ai-report-contract.ts` 需要升级为：

- 旧 7 字段继续保留解析
- 新增强字段以 phase3 增强字段方式解析
- 若 AI 漏掉增强字段，不报整页级错误，而是降级回旧摘要模式

这样可以保证：

- 第三阶段有渐进接入空间
- 测试与线上容错更稳

### 6.3 页面消费链：AI 主结论真正吃 AI 增强摘要

`src/lib/trinity-analysis-page-view-model.ts` 与 `src/components/stock/AnalysisSummaryPanel.tsx` 需要升级成：

1. AI 摘要增强字段优先覆盖 AI 结论头。
2. 若增强字段齐全，则直接展示：
   - 当前综合判断
   - 当前最关键原因
   - 时空摘要
   - 结构摘要
   - 执行摘要
   - 候选结构摘要
   - 等待状态摘要
   - 判断疑点（若有）
3. 若增强字段缺失，则优雅降级回旧摘要 + 后端 fallback 模式。
4. Markdown 正文在 AI 区拥有明确承载位置，作为详细解读层显示。

### 6.4 第二阶段正式判断合同不再变动

第三阶段不再向 `deterministic_decision` 追加新的正式判断字段。  
它只消费第二阶段已稳定下来的字段，并把这些字段转换成更好的 AI 输出合同。

## 7. 测试与回归策略

第三阶段至少需要补以下四类测试。

### 7.1 route prompt 合同测试

锁住以下要求：

- AI 继续保留 `JSON 摘要 + Markdown 正文`
- JSON 摘要要求新增增强字段
- AI 可以输出条件升级预案
- AI 可以输出判断疑点
- 但 AI 不能把 `wait / avoid` 直接升级为正式 `buy / add`

### 7.2 parser 合同测试

锁住以下要求：

- 旧 7 字段仍能通过解析
- 新增强字段可被成功解析
- 缺少增强字段时可优雅降级
- 缺少 Markdown 正文仍报错

### 7.3 view model / 面板消费测试

锁住以下要求：

- AI 增强摘要能覆盖 AI 区主结论头
- 当前正式结论与 AI 条件升级预案能同时存在
- 判断疑点不会覆盖后端正式边界
- Markdown 正文能正常显示

### 7.4 行为边界测试

锁住以下要求：

- 当后端是 `wait / avoid` 时
- AI 可以写“若 X 则升级”
- 但不能写成“现在立即买入/加仓”的正式结论

## 8. 实施顺序

第三阶段建议按以下顺序实现：

1. 先升级 `AiSummaryCard` 与 parser 合同
2. 再升级 AI route prompt 与输出契约
3. 再升级页面 AI 区消费链
4. 最后补测试与回归验证

原因：

- parser 合同先落，才能让 route 有明确输出目标
- route 合同升级后，页面才能安全接新字段
- 页面消费链最后接管，便于兼容回退与验证

## 9. 验收标准

第三阶段完成后，应满足以下结果：

1. AI 仍然输出 `JSON 摘要 + Markdown 正文`。
2. JSON 摘要除旧字段外，新增 phase3 增强字段并能被 parser 消费。
3. 页面 AI 区主结论能正式展示 AI 的：
   - 当前综合判断
   - 当前最关键原因
   - 时空摘要
   - 结构摘要
   - 执行摘要
4. Markdown 正文能展示更详细的三位一体分析明细。
5. 当后端当前为等待/回避时，AI 不能直接把正式动作改写成买入/加仓。
6. AI 可以明确给出条件升级预案。
7. AI 可以指出后端结论与输入信号的疑点或张力。
8. 旧链路在增强字段缺失时仍能正常回退。

## 10. 与后续阶段的关系

第三阶段完成后：

- 页面主 AI 区将真正与第二阶段判断合同对齐
- AI 与页面将共享同一套正式判断源
- 条件升级预案与判断疑点会成为正式交互能力

如果后续仍需继续增强，可以单独进入下一阶段，例如：

- 把 Markdown 中的某些高价值段落进一步结构化展示
- 把 AI 的条件升级预案拆成更细的前端块
- 引入更严格的疑点分级与诊断标签

但这些都不属于第三阶段范围。
