# 三位一体分析页可解释表达统一设计

## 0. 背景

`2026-04-19-trinity-global-analysis-page-ux-upgrade-design.md` 已经完成了页面级信息架构重组，把分析页明确拆成：

- 页面级综合结论
- 主策略硬门控
- 交易周期总线
- 三位一体规则链
- 周期详情

但在真实界面落地时，仍然出现了新的表达问题：

1. `交易周期总线`、`三位一体规则链`、`周期详情` 经常只给结论，不给用户能直接读懂的交易解释。
2. 页面里已经开始使用 `约束`、`触发`、`确认` 等交易术语，但术语背后的逻辑没有被统一展开，用户只能看到抽象结果。
3. 同一类信号在不同区域使用不同词、不同颜色、不同表达长度，用户需要重复学习。
4. 某些底层逻辑说明本身没有错，但直接摆在卡面主内容里，会挤压真正重要的“当前怎么看、现在怎么做”。
5. 现在线上版本的结构骨架已经基本可用，本次更适合做“表达层增强”，而不是再次重写页面骨架。

因此，本设计不再重做分析页结构，而是定义一套统一的表达规则：

> 在保留现有线上骨架的前提下，让 `交易周期总线`、`三位一体规则链`、`周期详情` 都能先给出用户看得懂的当前判断、分析与操作建议；同时通过 hover 统一解释术语、限制条件、触发条件与判定依据。

## 1. 目标与非目标

### 1.1 目标

本次设计目标有四个：

1. 让 `交易周期总线`、`三位一体规则链`、`周期详情` 形成统一的阅读方式。
2. 保留 `约束`、`触发`、`确认` 等交易术语，但要求每个术语都能通过 hover 解释清楚具体逻辑。
3. 让表层内容保持精简，优先回答“当前状态判断、为什么这么看、现在建议怎么做”。
4. 为背离、时空、突破/跌破、量能、均线、结构、级别、执行建立统一的信号标签系统与颜色语义。

### 1.2 非目标

本次设计明确不做以下事情：

1. 不重写分析页整体信息架构。
2. 不推翻现在线上 `交易周期总线`、`三位一体规则链`、`周期详情` 的骨架与顺序。
3. 不新增交易算法，不改后端判定逻辑，不改变已有策略语义。
4. 不把所有解释都搬到主卡片上，避免再次造成主内容过载。

## 2. 核心原则

### 2.1 保留线上骨架，重做表达规则

本次设计默认保留现在线上版本的外部结构：

- `交易周期总线` 继续保留三张组合卡与四个信息块
- `三位一体规则链` 继续保留六张规则卡
- `周期详情` 继续保留分周期 Tab 与各自详情区

优化重点放在：

- 主内容说什么
- hover 说什么
- 术语怎么解释
- 信号标签如何统一

### 2.2 表层必须先回答交易问题

任何模块的表层内容，都必须优先回答以下三个问题：

1. 当前状态判断是什么？
2. 为什么现在是这个状态？
3. 现在建议怎么做？

禁止在表层优先堆叠以下内容：

- 长段判定依据
- 原始字段
- 系统内部语言
- 无法直接转成动作的抽象说明

### 2.3 术语可以保留，但不能只抛结论

`约束`、`触发`、`确认`、`取消`、`失效` 这些交易术语都允许继续使用，但有一个强约束：

> 只要表层出现术语，hover 就必须能解释它到底指什么、为什么成立、下一步怎么看。

例如：

- `存在约束`
  不是可接受的最终表述。

- `日线约束：等待平台边界确认`
  可以作为表层短句。

但 hover 必须继续解释：

- 什么叫等待平台边界确认
- 为什么日线现在没有放行
- 当前到底卡在结构、时空、均线、量能还是级别
- 确认后子级别动作如何升级

### 2.4 表层精简，hover 讲透

本次设计采用统一分层：

- 表层：短句、结论、标签、建议
- hover：术语解释、逻辑展开、条件细节、判定依据

表层不是“所有细节摘要”，而是“帮助用户快速判断要不要继续看下去”。

hover 不是“锦上添花”，而是负责把术语讲透的必要解释层。

### 2.5 统一信号标签语言

背离、时空、突破/跌破、量能、均线、结构、级别、执行等信号，必须统一成同一种展示语法：

```text
类别｜结果
```

例如：

- `时空｜中偏弱`
- `背离｜顶背离`
- `突破/跌破｜突破候选`
- `量能｜突破量弱`
- `均线｜MA55压制`

## 3. 三模块统一信息模板

本节定义 `交易周期总线`、`三位一体规则链`、`周期详情` 的统一输出模板。

### 3.1 表层模板

三个模块都统一遵守以下表层模板：

1. `当前状态判断`
2. `一句分析`
3. `一句操作建议`
4. `少量关键信号标签`

具体定义如下：

- `当前状态判断`
  表示当前可执行度与方向判断，例如：
  - `可执行`
  - `观察中`
  - `谨慎看`
  - `暂不做`

- `一句分析`
  用交易语言解释当前状态，例如：
  - `日线还没完全放行，30分钟先看确认`
  - `延伸结构可观察，但不能按标准节点操作`
  - `MA55仍在压制，均线关系没完全放行`

- `一句操作建议`
  直接告诉用户当前建议动作，例如：
  - `先等30分钟突破确认`
  - `只把15分钟信号当节奏参考`
  - `先按边界看，不按标准节点下手`

- `少量关键信号标签`
  用统一标签系统概括最关键的 1-4 个信号。

### 3.2 hover 模板

三个模块都统一遵守以下 hover 模板：

1. 这句话是什么意思
2. 为什么这么判断
3. 当前限制 / 触发 / 确认 / 取消分别是什么
4. 判定依据和细节

若当前项不涉及某一类条件，可以缺省，但格式顺序应尽量稳定。

### 3.3 模板适用范围

本模板同时适用于：

- 交易周期总线
- 三位一体规则链
- 周期详情顶部结论区

## 4. 交易周期总线表达方案

### 4.1 保留线上骨架

交易周期总线继续保留现在线上的卡片结构：

1. 组合标题
2. 方向 / 状态 badge
3. 主句
4. 四个信息块：
   - `父级约束`
   - `触发级别`
   - `适合动作`
   - `主要风险`

本次不重排这四块，不换卡片层次。

### 4.2 主句职责

交易周期总线的主句不再承担“系统结构说明”的职责，而固定承担：

- 当前状态判断
- 一句分析
- 一句操作建议

推荐表达方式：

- `当前先看30分钟有没有突破确认，不直接放大动作`
- `当前只把15分钟信号当节奏参考，不直接升级成加仓动作`
- `当前先观察，等日线确认后再判断是否值得按中线去做`

以下表达降为次要信息，不再占主句：

- `周线定约束，日线给触发`
- `日线定约束，30分钟给触发`
- `60分钟定约束，15分钟给触发`

这些关系可以保留，但应放在：

- 副说明
- hover
- 小字弱提示

### 4.3 四个信息块的表层与 hover 分工

#### `父级约束`

表层只放短结论，例如：

- `日线：等待平台边界确认`
- `60分钟：等待触发或确认信号`
- `周线：等待更明确的回抽确认或突破确认`

hover 必须解释：

1. 这句话是什么意思
2. 为什么父级当前没有放行
3. 当前卡住的是结构、时空、均线、量能还是级别
4. 父级一旦放行，子级别动作如何升级

#### `触发级别`

表层继续保留级别名称，例如：

- `30分钟`
- `15分钟`
- `日线`

hover 必须解释：

1. 这个级别负责看什么
2. 当前要看的具体现象是什么
3. 是突破、跌破、回踩、回抽，还是重新站回关键边界

#### `适合动作`

表层只放动作词，例如：

- `等待`
- `观察`
- `轻仓验证`
- `做T`
- `跟踪持有`

hover 必须解释：

1. 为什么现在是这个动作
2. 为什么不是更强动作
3. 升级动作还缺什么条件

#### `主要风险`

表层只放一句最关键风险，例如：

- `当前仅满足观察，不满足执行`
- `确认不足，容易回落失效`
- `子级别信号容易被父级别否决`

hover 必须解释：

1. 当前最大失败点是什么
2. 什么情况下取消这套预案
3. 如果走坏，应退回到什么动作级别

### 4.4 标签预算

交易周期总线每张卡建议展示 `2-3` 个关键信号标签。

推荐优先级：

1. 父级时空或结构信号
2. 子级突破/跌破或执行信号
3. 量能或级别权限信号

## 5. 三位一体规则链表达方案

### 5.1 保留线上六卡结构

三位一体规则链继续保留现有六张卡与顺序：

1. `结构资格`
2. `MACD 时空`
3. `55 / 233 线关系`
4. `量能确认`
5. `级别权限`
6. `执行计划`

本次不拆并、不换序、不改成全新卡片体系。

### 5.2 每张卡的表层模板

每张规则卡表层固定展示：

1. `状态判断`
2. `一句分析`
3. `一句操作建议`
4. `1-2 个关键信号标签`

示例：

- `结构资格`
  - 状态：`谨慎看`
  - 分析：`延伸结构可观察，但不能按标准节点操作`
  - 建议：`先按边界看，不按标准节点下手`
  - 标签：`结构｜延伸C`

- `MACD 时空`
  - 状态：`可执行`
  - 分析：`中偏弱允许继续跟踪，但还不支持放大动作`
  - 建议：`继续跟踪当前执行段`
  - 标签：`时空｜中偏弱`

- `55 / 233 线关系`
  - 状态：`谨慎看`
  - 分析：`MA55仍在压制，均线关系没完全放行`
  - 建议：`等有效站上MA55再升级判断`
  - 标签：`均线｜MA55压制`

### 5.3 每张卡的 hover 模板

每张规则卡 hover 统一解释：

1. 这句话是什么意思
2. 为什么这么判断
3. 当前限制是什么
4. 下一步条件是什么
5. 判定依据是什么

这意味着：

- 规则卡表层负责“当前怎么看、怎么做”
- hover 负责“为什么这样判”

### 5.4 标签预算

三位一体规则链每张卡最多展示 `1-2` 个标签。

如果某张卡标签过多，应优先保留最能说明当前状态的那个标签，避免再次回到字段堆叠。

## 6. 周期详情表达方案

### 6.1 保留现有 Tab 结构

周期详情继续保留按级别切换的 Tab：

- `周线`
- `日线`
- `60分钟`
- `30分钟`
- `15分钟`

### 6.2 每个周期 Tab 顶部新增结论头

每个周期详情的顶部，应先提供一个 `周期结论头`，统一展示：

1. `当前状态判断`
2. `一句分析`
3. `一句操作建议`
4. `4-6 个统一信号标签`

例如：

- 当前状态：`观察中`
- 分析：`延伸C仍成立，但MA55未完全放行`
- 建议：`先看平台边界确认，不按标准节点提前下手`
- 标签：
  - `结构｜延伸C`
  - `时空｜中偏弱`
  - `均线｜MA55压制`
  - `量能｜突破量弱`

结论头之后，继续保留现有：

- 结构
- 时空
- 均线
- 量能
- 执行
- 证据区

但应尽量复用统一标签与统一颜色语言，避免每个区域重新发明命名方式。

### 6.4 周期详情中的重点信号

以下信号应优先纳入周期详情顶部结论头或信号带：

- 时空信号

## 8. 标签 hover 统一模板

任何可 hover 的信号标签，统一按以下格式解释：

1. `信号含义`
2. `为什么成立`
3. `交易含义`
4. `什么情况下失效或降级`

示例：

`突破/跌破｜普通突破`

hover 应解释为：

- 价格已经穿越关键边界
- 但实体或量能还不够强
- 当前只能当候选，不直接升级动作
- 如果很快跌回原边界，这个信号降级

## 9. 数据映射原则

本次设计不新增新的交易逻辑，而是优先复用已有数据契约。

信号标签与文案来源按以下优先级映射：

1. 优先使用 `trinity_decision` 的结构化结果
2. 若 `trinity_decision` 未覆盖，再使用周期级原始字段
3. 若表层需要交易解释，则通过 view model 层把结构化字段翻译为统一标签与短句

本次不要求后端立刻补全所有新字段，但前端表达层必须先统一：

- 标签语法
- 颜色语义
- hover 契约
- 三模块表层模板

## 10. 验收标准

本设计完成后，应满足以下验收标准：

1. `交易周期总线`、`三位一体规则链`、`周期详情` 三个模块都能先给出用户看得懂的当前判断、分析与操作建议。
2. 页面表层允许继续使用 `约束`、`触发`、`确认` 等术语，但 hover 必须能解释清楚背后逻辑。
3. 现在线上骨架不被推翻，用户仍能识别原有页面结构。
4. 背离、时空、突破/跌破、量能、均线、结构、级别、执行使用统一标签语法与颜色语义。
5. 表层内容明显比原始字段堆叠更短、更清晰；详细推理主要迁移到 hover。
6. 周期详情不再只是原始字段区，而是也具备“当前状态判断 + 分析 + 操作建议 + 标签”的结论头。
