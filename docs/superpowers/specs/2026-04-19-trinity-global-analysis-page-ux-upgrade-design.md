# 三位一体分析页全局 UX 升级设计

## 0. 背景

当前分析页已经具备三位一体 v2 决策内核、AI 综合判断、后端硬门控、级别决策总线、规则链和周期详情等模块，但页面体验开始出现系统性问题：

1. `AI 综合判断`、`后端硬门控`、`级别决策总线`、`三位一体规则链`、`周期详情`之间缺少统一的语义分层。
2. “全局”“主判定”“周期详情”这三个概念混在一起，用户容易误以为全局判断就是日线判断。
3. 标签颜色语义不统一，有时表示状态，有时又像表示方向。
4. 同一类结构标签在不同区域展示样式不一致，例如 `C单平台式`、`延伸C类`。
5. 许多结论只给结果，不解释来源，例如 `结构共振已成立`、`大背景偏空`。
6. 周期详情内部卡片嵌套过深，同时存在与顶部模块重复的信息，例如执行动作、仓位约束、规则摘要。
7. AI 综合判断中的触发条件、风险条件、风控约束和后端硬门控未明确作用级别，用户无法判断它们来自日线、30分钟，还是三条交易组合的综合。

因此，本次不再只优化某一个标签或某一个卡片，而是从全局视角重新定义分析页的用户体验、视觉语法和信息契约。

## 1. 核心定义

### 1.1 页面级综合结论

页面级综合结论不等于日线，也不等于任意单一级别。

页面级综合结论定义为：

> 基于三条交易组合综合判断后，给出当前这只股票最优先的交易策略、主约束级别、触发级别、风险边界和风控约束。

三条交易组合为：

1. `中线主策略组合｜周线 → 日线`
2. `短线执行组合｜日线 → 30分钟`
3. `超短线 / T 组合｜60分钟 → 15分钟`

页面顶部的 AI 综合判断必须服务于这个定义。

### 1.2 主策略硬门控

当前页面里的“后端硬门控”并不是天然全局门控。现有实现中，它来自前端选出的一个 `primaryDecision`，而 `primaryDecision` 当前按固定顺序选择：

```text
日线 → 周线 → 60分钟 → 30分钟 → 15分钟
```

这说明当前硬门控更准确地叫：

> 主判定级别硬门控

新版页面中，应升级为：

> 主策略硬门控

它必须明确展示：

- 来源组合：例如 `短线执行组合｜日线 → 30分钟`
- 主约束级别：例如 `日线`
- 触发级别：例如 `30分钟`
- 是否来自后端显式综合结果，或来自前端降级选择

### 1.3 交易周期总线

原 `级别决策总线` 升级为 `交易周期总线`。

它不再展示抽象的 `维度一 / 维度二 / 维度三`，而是展示三套交易组合：

| 交易组合 | 级别关系 | 策略含义 | 关键问题 |
| --- | --- | --- | --- |
| `中线主策略组合` | 周线 → 日线 | 周线定大背景、方向和仓位上限；日线定中线结构和主策略窗口 | 这只票是否值得按一段中线行情做？ |
| `短线执行组合` | 日线 → 30分钟 | 日线定主策略和风险边界；30分钟找触发、回踩确认和买卖点 | 日线思路成立时，短线在哪里动手？ |
| `超短线 / T 组合` | 60分钟 → 15分钟 | 60分钟定短周期节奏；15分钟负责细触发和快进快出 | 是否只适合做 T 或盘中节奏？ |

### 1.4 周期详情

周期详情不再承担页面级综合判断职责。

周期详情定义为：

> 每个单一级别的解释与证据区，用于查看该级别自己的结构、时空、均线、量能、触发、风险和拓扑证据。

周期详情应使用子 Tab 切换：

- `周线`
- `日线`
- `60分钟`
- `30分钟`
- `15分钟`

每个子 Tab 采用方案 A：

1. 该级别的简明决策卡
2. 该级别的规则摘要
3. 该级别的证据区

不在每个级别里完整复制顶部结构，避免页面重复。

## 2. 全局页面信息架构

新版页面从上到下按以下顺序组织：

1. **顶部数据状态条**
   - 行情数据、同步状态、AI 生成状态、本次判定使用的数据范围。

2. **页面级综合结论**
   - 默认展示后端确定性综合摘要。
   - 用户点击后生成 AI 综合判断。
   - 明确展示优先交易组合、主约束级别、触发级别。

3. **主策略硬门控**
   - 明确当前策略不能突破哪些后端硬约束。
   - 每个门控项提供 hover 解释。

4. **交易周期总线**
   - 展示中线、短线、超短线 / T 三条交易组合。
   - 用于解释页面级综合结论是从哪些组合中综合得出的。

5. **全局规则链摘要**
   - 展示当前优先组合或主策略级别的六段规则链摘要。
   - 不替代周期详情。

6. **周期详情子 Tab**
   - 每个级别展示自己的简明决策卡、规则摘要和证据。
   - 作为复盘、解释和排错区域。

7. **AI 正文 / 复盘展开内容**
   - 放在用户主动展开或 AI 已生成后查看，不抢首屏主结论。

## 3. 页面级综合结论设计

### 3.1 必须回答的问题

页面级综合结论必须一屏内回答：

1. 当前优先策略是什么？
2. 当前优先交易组合是哪一条？
3. 主约束级别是什么？
4. 触发级别是什么？
5. 当前方向是偏多、偏空，还是中性？
6. 当前动作是可执行、观察中、谨慎看，还是暂不做？
7. 触发条件、风险条件、风控约束分别是什么？

### 3.2 默认态

AI 尚未生成时，页面不等待 AI。

默认态展示：

- `AI 综合判断尚未生成`
- `生成 AI 综合判断`按钮
- 后端确定性综合摘要
- 当前优先交易组合
- 主约束级别
- 触发级别
- 当前方向
- 当前动作
- 主策略硬门控

默认态必须明确说明：

> 页面已先展示后端确定性结论。点击后，AI 会在后端硬门控范围内综合三条交易组合，生成策略摘要。

### 3.3 AI 结果态

AI 结果态的主标题是 AI 生成的一句话策略结论，但必须被后端硬门控约束。

AI 结果态必须展示：

- AI 最终一句话策略结论
- 当前优先交易组合
- 主约束级别
- 触发级别
- 当前方向
- 当前动作
- 主因
- 触发条件
- 风险条件
- 风控约束

AI 不能把后端 `等待 / 规避 / 空仓等待` 升级成 `买入 / 加仓`。

### 3.4 作用域提示

AI 综合判断区域必须显式展示作用域，例如：

```text
综合范围：中线主策略组合、短线执行组合、超短线 / T 组合
当前优先组合：短线执行组合｜日线 → 30分钟
主约束级别：日线
触发级别：30分钟
```

这样可以解决“触发条件、风险条件、后端硬门控到底是不是日线级别”的歧义。

## 4. 主策略硬门控设计

### 4.1 命名

页面不再单独使用模糊的 `后端硬门控` 作为用户主标题。

推荐标题：

```text
主策略硬门控
```

副说明：

```text
这些是当前优先交易组合不能突破的后端约束。
```

若后端尚未提供组合级综合结果，则需要说明：

```text
当前硬门控来自主判定级别：日线
```

### 4.2 展示字段

主策略硬门控建议展示：

- 来源组合
- 主约束级别
- 触发级别
- 后端最终动作
- 交易模式
- 仓位权限
- 结构资格
- 聚焦结构
- 量能状态
- 结论约束

### 4.3 Hover 解释

每个硬门控项都必须支持 hover 解释。

hover 固定回答：

1. 这是什么
2. 当前值意味着什么
3. 对交易有什么限制
4. 数据来源

示例：`仓位权限`

```text
这是什么：后端允许的最大仓位动作范围。
当前值：轻仓试探。
交易限制：AI 不能升级为满仓买入或连续加仓，只能在触发条件成立后轻仓验证。
数据来源：当前优先组合硬门控 / 主判定级别 trade_qualification.position_permission。
```

## 5. 交易周期总线设计

### 5.1 从级别决策总线升级

原标题：

```text
级别决策总线
```

建议新标题：

```text
交易周期总线
```

副标题：

```text
用三条交易组合综合判断当前最适合做中线、短线、超短线 / T，还是继续等待。
```

### 5.2 三张组合卡

每张组合卡固定展示：

- 交易组合名称
- 级别关系
- 方向：偏多 / 偏空 / 中性
- 可执行度：可执行 / 观察中 / 谨慎看 / 暂不做
- 父级约束
- 触发级别
- 适合动作
- 主要风险

### 5.3 三条组合的职责

#### 中线主策略组合｜周线 → 日线

职责：

- 判断大方向和中线交易价值。
- 周线决定趋势背景与仓位上限。
- 日线决定中线结构、主策略窗口和主要风控边界。

页面语义：

```text
这只股票是否值得按一段中线行情去做。
```

#### 短线执行组合｜日线 → 30分钟

职责：

- 在日线策略允许的前提下寻找短线触发点。
- 日线给主策略和风险边界。
- 30分钟给具体进场、回踩确认、突破确认或止损触发。

页面语义：

```text
日线思路成立时，短线在哪里动手。
```

#### 超短线 / T 组合｜60分钟 → 15分钟

职责：

- 判断盘中节奏、T 交易和快进快出机会。
- 60分钟定短周期方向和节奏。
- 15分钟给微观触发和退出点。

页面语义：

```text
是否只适合做 T 或盘中节奏，不能反向推翻上级硬门控。
```

### 5.4 组合间约束

三条组合不是完全平级互相替代，而是有约束关系：

1. 中线组合决定大方向和较大仓位是否允许。
2. 短线组合决定主策略能否触发和执行。
3. 超短线 / T 组合只能优化执行节奏，不能反向推翻中线或短线硬门控。

示例：

- 中线偏多但短线未触发：`中线观察，短线等待触发`
- 日线不支持交易但 15 分钟走强：`只允许超短观察或做 T，不能升级为买入`
- 周线偏空但 30 分钟反弹：`短线反弹可观察，仓位和目标必须降级`

## 6. 全局颜色与标签体系

### 6.1 颜色只表达方向

全页面统一：

| 颜色 | 含义 |
| --- | --- |
| 红色 | 偏多 / 看多 / 多头方向 |
| 绿色 | 偏空 / 看空 / 空头方向 |
| 灰色 | 中性 / 等待 / 未确认 / 无明确方向 |

颜色不再表达 `通过 / 警示 / 提示 / 失败`。

### 6.2 状态词只表达可执行度

全页面统一使用：

| 状态词 | 含义 |
| --- | --- |
| 可执行 | 当前条件已满足，可纳入执行判断 |
| 观察中 | 有方向或预案，但仍需确认 |
| 谨慎看 | 存在约束或风险，不能放大动作 |
| 暂不做 | 当前条件不支持交易 |

### 6.3 结构标签统一

结构标签必须全局统一，包括：

- AI 综合判断
- 主策略硬门控
- 交易周期总线
- 规则链
- 周期详情
- 结构拓扑说明

同一结构类型只能有一套展示样式。

示例结构标签：

| 结构类型 | 展示建议 |
| --- | --- |
| C单平台式 | `C单平台式` |
| 延伸C类 | `延伸C类` |
| B双平台式 | `B双平台式` |
| D三段式 | `D三段式` |
| 未完成结构 | `未完成结构` |
| 复杂结构 | `复杂结构` |

结构标签颜色不应与交易方向冲突。结构标签建议使用结构家族固定色或中性色，方向另用红 / 绿 / 灰表达。

## 7. 全局 Hover 体系

### 7.1 Hover 分类

页面 hover 分为四类：

1. **规则定义 hover**：解释这个模块是什么。
2. **状态 hover**：解释当前状态为什么是可执行、观察中、谨慎看或暂不做。
3. **硬门控 hover**：解释硬门控字段对交易有什么限制。
4. **结构标签 hover**：解释结构类型、当前标准 / 延伸 / 未完成状态，以及为什么这样归类。

### 7.2 Hover 内容要求

所有 hover 都必须避免只堆字段，固定回答用户问题。

推荐结构：

```text
这是什么
当前值是什么意思
为什么这样判断
对交易有什么影响
数据来源
```

对于空间有限的 hover，可保留前三项，但 `对交易有什么影响` 不能长期缺失。

## 8. 周期详情子 Tab 设计

### 8.1 子 Tab 结构

周期详情改为 Tabs：

```text
周线｜日线｜60分钟｜30分钟｜15分钟
```

默认打开：

1. 若当前优先组合有主约束级别，默认打开主约束级别。
2. 否则默认打开日线。
3. 若日线缺失，打开第一个有数据的级别。

### 8.2 每个 Tab 的内容

每个级别采用方案 A：

1. **该级别简明决策卡**
   - 当前方向
   - 当前动作
   - 结构标签
   - 关键约束
   - 触发条件
   - 风险条件
   - 风控约束

2. **该级别规则摘要**
   - 结构
   - 时空
   - 均线
   - 量能
   - 级别权限
   - 执行计划

3. **该级别证据区**
   - 结构拓扑
   - 起点 / 当前段 / 下一确认
   - MACD 时空证据
   - 55 / 233 均线关系
   - 量能证据
   - 场景路径与改判条件

### 8.3 周期详情不再重复顶部结构

周期详情不应完整复制：

- AI 综合判断
- 主策略硬门控
- 三条交易组合总线

周期详情只解释单一级别：

```text
这个级别自己怎么看，证据是什么，触发和风险在哪里。
```

## 9. 周期详情解释增强

### 9.1 结构共振已成立

不能只展示：

```text
结构共振已成立
```

必须同时展示：

- 共振对象：例如 `周线 → 日线`
- 当前级别：例如 `日线`
- 共振依据：结构、时空、均线、量能中哪些成立
- 仍需确认：缺什么触发或风险约束

示例：

```text
结构共振已成立
共振对象：周线 → 日线
成立依据：周线偏多，日线结构未破坏，日线时空允许观察
仍需确认：30分钟放量突破后再触发执行
```

### 9.2 大背景

不能只展示：

```text
大背景：偏空
说明：上一级时空状态给出的方向背景
```

必须明确：

- 上一级是谁
- 当前级别是谁
- 背景来源是什么

示例：

```text
大背景：偏空
上一级：周线
当前级别：日线
背景来源：周线时空状态 + 周线结构方向
交易含义：日线反弹只能降级观察，不直接放大仓位
```

### 9.3 执行动作与仓位约束

周期详情里的 `执行动作` 和 `仓位约束` 必须与该级别的三位一体判定统一。

如果该级别存在 `trinity_decision`，则优先使用：

- `trinity_decision.conclusion`
- `trinity_decision.execution`
- `trinity_decision.trade_qualification`

如果该级别没有 `trinity_decision`，才回退到结构解释链路中的旧执行字段。

页面必须标注来源：

```text
来源：日线三位一体判定
```

或：

```text
来源：结构解释链路回退
```

## 10. 数据契约升级

interface GlobalStrategyViewModel {

  primaryCombination: TradingCombinationKey;
  primaryCombinationLabel: string;

  primaryReason: string;

  guardrails: string[];
}

### 10.4 后端与前端责任边界

短期：

## 11. 实施阶段

### Phase 1：统一术语与数据契约

- 将 `全局` 改为 `页面级综合结论`。
- 将 `级别决策总线` 改为 `交易周期总线`。
- 将 `后端硬门控` 改为 `主策略硬门控`。
- 建立红 / 绿 / 灰方向颜色体系。
- 建立 `可执行 / 观察中 / 谨慎看 / 暂不做` 状态体系。

### Phase 2：升级顶部综合区与硬门控

- 综合区展示优先交易组合、主约束级别、触发级别。
- 主策略硬门控增加来源说明与 hover 解释。
- AI 摘要明确综合范围和作用级别。

### Phase 3：升级交易周期总线

- 三张组合卡替换原维度卡。
- 展示方向、可执行度、父级约束、触发级别、适合动作、主要风险。
- 明确中线、短线、超短线 / T 的职责。

### Phase 4：升级全局规则链与标签体系

- 状态标签改为交易语言。
- 颜色改为方向语义。
- 结构标签统一。
- 状态 hover、规则 hover、结构 hover 语义分离。

### Phase 5：周期详情改为子 Tab

- 周线 / 日线 / 60分钟 / 30分钟 / 15分钟子 Tab。
- 每个 Tab 展示简明决策卡、规则摘要和证据区。
- 去除周期详情内部重复嵌套和重复卡片。

### Phase 6：解释增强与回归验证

- 补齐 `结构共振已成立`、`大背景`、`执行动作`、`仓位约束` 的来源说明。
- 测试用户可见文案不泄漏内部枚举。
- 测试所有颜色均来自方向，不来自状态。
- 测试所有顶部结论均标注作用范围。
