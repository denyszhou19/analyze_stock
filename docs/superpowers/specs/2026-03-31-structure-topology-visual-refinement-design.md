# 结构拓扑视觉清理设计

## 背景

当前分析页已经接入了 `structure.interpretation`，能表达：

- 背景
- 原型
- 成熟度
- 当前段
- 下一确认
- 改判路径

但实际 UI 仍存在明显的可读性问题，尤其在 60 分钟、30 分钟这类中短周期上更突出：

1. 图上的“起点 / 当前”贴纸会挡住价格标签。
2. `live` 尾段同时使用高亮圈、虚线、编号叠字，视觉噪音过高。
3. 顶部 badge、正文描述、下方摘要卡存在重复表达。
4. 对复杂 / 未完成结构，直接暴露 `p7` 这类内部锚点编号，用户无法理解。
5. 单个标签内混入多类信息，例如“原型 + 成熟度 + 峰值图标”或“当前段 + 状态 + 方向”，导致扫描成本高。

因此，这次不再新增新的结构语义，而是补一份聚焦的视觉清理 spec，只解决“怎么让已有语义被更清楚地看见”。

## 目标

- 让拓扑图本体更干净，价格标签优先可读。
- 让 `live` 尾段看起来像“正在形成的延续”，而不是一段突兀的施工线。
- 消除同一信息在多个区域重复出现的问题。
- 把“结构起点”明确表达为“聚焦结构的起点”，减少“为什么不是最左边”的误解。
- 隐藏 `p7` 这类内部实现编号，不把系统内部锚点直接暴露给用户。
- 把“聚焦起点 / 最后确认点 / 进行中点 / 当前段”四类角色彻底区分，避免把历史确认点误叫成“当前”。
- 让每个 badge / 标签只承担一种职责。

## 非目标

- 不修改结构识别算法。
- 不修改 `interpretation` 的总体语义模型。
- 不在本次引入复杂的 hover 联动或点击联动。
- 不在本次重做整页风格系统，只清理当前结构面板与拓扑图的视觉表达。

## 问题归因

### 1. 图层冲突

当前图上同时存在：

- 价格标签
- 点编号
- 起点 / 当前贴纸
- live 终点编号

它们都围绕同一个点位摆放，导致局部区域过密，价格信息被压住。

### 2. `live` 的视觉语言过重

`live` 现在同时拥有：

- 明亮外圈
- “当前”文字贴纸
- 虚线延长段
- 末端编号

这让用户第一眼看到的不是结构走势，而是一个风格不协调的强调元素。

### 3. 信息重复

当前页面至少三处在重复表达同一组信息：

- 顶部 badge
- “识别为 X，趋势 Y”正文
- 图下四宫格摘要

用户阅读时会感觉内容很多，但新增认知很少。

### 4. 文案没有区分“聚焦起点”和“整段走势左端”

对峰值切片或复杂结构来说，当前展示的是“本轮分析聚焦结构的起点”，不是“整张图最左边的第一笔”。

UI 如果仍写成“结构起点”，但不说明这是聚焦结构视角，就容易让用户误判。

### 5. 内部编号泄漏

`p7` 适合内部 explainability / render payload 使用，不适合作为面向用户的主展示编号。

用户可理解的是：

- `a1 / c1 / d3` 这类标准结构编号
- 或“聚焦起点 / 最后确认点 / 当前段”这类角色化文案

### 6. “当前”语义错位

当前图上实际混用了三种不同概念：

- `聚焦起点`
  当前被分析结构切片从哪里开始算
- `阶段锚点`
  旧 `prediction.current_stage` 对应的历史确认点
- `最新点`
  也就是最新价格点，若尚未确认，属于进行中点

现有 UI 把 `prediction.current_stage` 对应点直接叫成“当前”，会导致明显误导。

以用户指出的例子为准：

- `181.9` 是聚焦结构起点
- `170.4` 最多只能算旧的阶段锚点
- `150.8` 才是最新价格点，也就是进行中点

因此，本次要明确：

- “当前”一词不再用于历史确认点
- 历史点如果需要展示，只能叫“最后确认点”或“阶段锚点”
- 最新未确认点统一叫“进行中点”

## 总体方案

本次采用“去贴纸、降噪声、强分工”的方案。

### 一句话概括

- 图上只保留走势、价格、少量编号和轻量高亮。
- 结构语义主要在图外摘要区表达。
- badge 不再混装多个概念。

## 角色语义规则

本次新增一层强约束，统一图上和图下的角色定义。

### 1. 聚焦起点

- 指 `focus_structure.start_anchor`
- 表示“当前分析聚焦结构从哪里开始算”
- 它不是整张图最左侧点
- 它也不是“当前点”

### 2. 最后确认点

- 指当前进入进行中尾段之前，最后一个已经确认的拐点
- 例如 `164.6`
- 它是当前段的起点
- 若要在图上强调，可以用轻量编号或次级说明表达

### 3. 进行中点

- 指最新价格点
- 如果该点尚未形成正式确认拐点，则它就是进行中点
- 例如 `150.8`
- UI 文案统一使用“进行中”，不再直接向用户展示 `live`

### 4. 当前段

- 指“最后确认点 → 进行中点”这段
- 例如 `164.6 → 150.8`
- 它才是当前真正正在走的那一段

### 5. 阶段锚点

- 旧 `prediction.current_stage` 对应点如果不是最新点，只能作为“阶段锚点”存在
- 它不能再承担“当前点”的 UI 语义
- 默认情况下，页面不需要显式展示这个词
- 如果要保留，只能放在补充说明里，不能放到主高亮位置

### 6. UI 用词强约束

- 禁止把 `prediction.current_stage` 对应历史点直接标成“当前”
- 禁止在默认 UI 中直接展示 `live`
- 默认用户文案统一为：
  - `聚焦起点`
  - `最后确认点`
  - `进行中点`
  - `当前段`

## 视觉与交互规则

### 1. 点位高亮规则

#### 聚焦起点

- 仍然高亮，但改为“琥珀色外环”
- 不再在点上方额外挂“起点”贴纸
- 若存在标准编号（如 `c1`），保留编号
- 若不存在标准编号，不强行显示内部锚点号

#### 进行中点

- 改为“青色细外环 + 正常点心”
- 不再显示“当前”贴纸
- 不再显示 `live` 英文标记
- 若需要提示状态，仅在图外使用“进行中”

#### 最后确认点

- 如需强调，只使用轻量编号或小范围视觉强调
- 不再给它“当前”主视觉待遇

### 2. 进行中尾段规则

- 当前进行中的尾段保留虚线语义
- 但线宽要比当前实现更细
- 颜色从高饱和亮绿改为低饱和、半透明的冷色
- 末端点使用轻量强调，不再做过重描边

目标效果：

- 用户能看出“这段还在形成中”
- 但不会抢走整张图的主视觉注意力

### 3. 图上文本规则

- 价格标签优先级最高，不能再被“起点 / 当前”文案遮挡
- 点编号只保留必要编号：
  - 标准结构：保留 `a1 / c2 / c4 / c6` 这类关键点
  - 复杂结构：不展示 `p7 / p15` 这类内部点号
- 图上如需表达进行中状态，使用中文“进行中”放在图外，不在点位旁叠英文 `live`
- 若点位过密，优先保价格标签，其次保关键编号，再次保其他辅助文字

### 4. badge 分工规则

拓扑标题区的 badge 固定拆成以下几类：

- `背景`
- `原型`
- `成熟度`
- `当前段`
- `拐点数`

规则：

- 一个 badge 只放一个概念
- 不允许把“原型 + 成熟度 + 图标”塞进同一个 badge
- 峰值或切片类辅助标记，如确有必要，作为独立小徽标出现，不与主文案混写
- 禁止在 badge 中同时出现“点编号 + 价格 + 状态”三类信息

### 5. 摘要卡规则

图下摘要卡固定改为：

1. `聚焦起点`
2. `最后确认点`
3. `进行中点`
4. `下一确认`

说明：

- 原“结构起点”统一改名为“聚焦起点”
- 用词上明确它是“当前分析焦点的起点”
- `最后确认点` 和 `进行中点` 分开显示，不再把历史点误当成当前
- `参考原点` 不再占主摘要卡位，改为放在“聚焦起点”的次级说明里
- 这样可以避免一个卡片里同时混“点号 / 价格 / 日期 / 参考原点 / 当前状态”多层信息

### 6. 正文去重规则

删除或下线这类重复正文：

- `识别为C单平台式，震荡趋势`
- `识别为延伸A类，上涨趋势`

原因：

- 这些信息已经被 badge 与摘要卡覆盖
- 正文应留给真正新增的信息，而不是重复摘要

### 7. `p7 / p15` 之类编号的展示规则

#### 标准结构

- 允许显示 `a1 / b3 / c5 / d4`

#### 复杂 / 未完成结构

- 默认不显示 `p7 / p15`
- 若必须表达该点的重要性，使用角色化文案：
  - `聚焦起点`
  - `最后确认点`
  - `进行中点`

即：

- `p7` 的来源是内部通用点号，即 `point 7`
- 它只用于后端 explainability / render payload / 调试定位
- 面向用户的默认文案不直接暴露 `p7`

## 数据映射规则

### 1. 起点文案

- 若 `focus_structure.start_anchor.point_id` 属于标准结构编号，则摘要卡显示：
  - `c1 @ 181.92`
- 若属于内部锚点，如 `p7`，摘要卡显示：
  - `181.92`
  - 不显示 `p7`

### 2. 最后确认点文案

- 显示最后一个已确认拐点价格
- 如存在标准编号，可显示为：
  - `c5 @ 164.60`
- 若不存在标准编号，则只显示价格：
  - `164.60`

### 3. 进行中点文案

- 显示最新价格点
- 默认文案为：
  - `150.80`
  - 次级说明：`进行中`
- 不显示 `live`

### 4. 参考原点文案

不再占主摘要卡位，只作为聚焦起点卡的次级说明显示为：

- `2026-02-25 @ 156.48`

不再加“参考原点”前缀进卡片正文。

### 5. 当前段文案

保持：

- `164.6 → 150.8`
- 第二行再显示：
  - `下行进行中`

不要合并成一个超长 badge。

### 6. 下一确认文案

拆成两层：

- 第一行：`等待 c6 拐点`
- 第二行：`突破点`

若 `next_confirmation` 无标准编号，则写成：

- `等待下一确认`
- 第二行保留触发类型，例如 `方向选择` / `突破确认`

## 版式规则

### 1. 顶部区域

从当前“多枚挤在一起的 badge”改成两排、低拥挤度布局：

- 第一排：背景 / 原型 / 成熟度
- 第二排：当前段 / 拐点数

### 2. 图下摘要区

- 保持四列桌面布局
- 每个卡片只展示一个主结论和一条辅助信息
- 卡片高度尽量接近，避免某一张卡因堆叠信息显著变高

### 3. 图内留白

- 上边距要给价格标签和锚点外环留足空间
- 进行中尾段末端不能贴近右边框
- 若当前点在上方密集区，优先自动错开编号与价格标签

## 验收标准

### 视觉验收

- 图上不再出现“起点 / 当前”贴纸遮挡价格标签
- 进行中尾段看起来更轻，不再显得突兀
- badge 的每一枚都只表达一类信息
- 上下重复文案明显减少

### 语义验收

- 用户能理解“聚焦起点”不是“整张图最左点”
- 复杂结构默认不再出现 `p7 / p15`
- 用户不会再把历史确认点误认成“当前点”
- 默认 UI 不再出现英文 `live`
- 标准结构仍保留 `a1 / c1 / d4` 这类有意义的编号

### 具体案例验收

以用户给出的两类案例为准：

#### C 平台案例

- 图上 `181.9` 可以作为“聚焦起点”高亮
- 图下显示 `聚焦起点 181.92`
- 图下单独显示 `最后确认点 164.60`
- 图下单独显示 `进行中点 150.80`
- `当前段` 表达为 `164.6 → 150.8，下行进行中`
- 不再强制把 `c1 @ 181.92` 与“参考原点”塞进同一卡片
- `进行中` 尾段明显更轻、更协调

#### 复杂 / 延伸 A 类案例

- 图下不再显示 `p7 @ 181.92`
- 改为仅显示 `聚焦起点 181.92`
- 若旧 `prediction.current_stage` 对应点是 `170.4`，它不能再显示成“当前”
- 最新点如为 `150.8`，则“进行中点”必须落在 `150.8`
- 若用户需要内部编号，应通过开发态调试信息或后续 hover 解释查看，而非默认主展示

## 与现有 spec 的关系

- 本 spec 是对 [2026-03-31-structure-explainability-ui-design.md](./2026-03-31-structure-explainability-ui-design.md) 的补充细化。
- 前者解决“需要展示什么”，本 spec 解决“怎么展示得不难看、不误导、不重复”。
- 本 spec 不修改 [2026-03-31-structure-interpretation-model-design.md](./2026-03-31-structure-interpretation-model-design.md) 的模型语义，只约束其前端呈现方式。
