# 结构拓扑视觉清理设计

## 背景

当前分析页已经接入了 `structure.interpretation`，能表达：

- 背景
- 原型
- 成熟度
- 当前段
- 下一确认
- 改判路径

但实际 UI 仍存在明显的可读性问题，尤其在 60 分钟、30 分钟这类中短周期上更突出：

1. 图上的“起点 / 当前”贴纸会挡住价格标签。
2. `live` 尾段同时使用高亮圈、虚线、编号叠字，视觉噪音过高。
3. 顶部 badge、正文描述、下方摘要卡存在重复表达。
4. 对复杂 / 未完成结构，直接暴露 `p7` 这类内部锚点编号，用户无法理解。
5. 单个标签内混入多类信息，例如“原型 + 成熟度 + 峰值图标”或“当前段 + 状态 + 方向”，导致扫描成本高。
6. 用户可见区域仍残留 `SCENARIO_PATHS`、`PREDICTION`、`LEFT_STRUCTURE_WARNING` 这类英文技术字段，破坏阅读体验。
7. 补充卡片缺乏层级，主结论、触发条件、补充解释的视觉权重接近，难以一眼抓重点。
8. 风险提醒卡大面积使用高饱和红粉色块，和整页风格不协调。
9. 部分级别的起点选择缺乏结构说服力，用户无法从图形节奏上自洽理解为什么这里会被识别为某个标准结构的起点。

因此，这次不再新增新的结构语义，而是补一份聚焦的视觉清理 spec，只解决“怎么让已有语义被更清楚地看见”。

## 目标

- 让拓扑图本体更干净，价格标签优先可读。
- 让 `live` 尾段看起来像“正在形成的延续”，而不是一段突兀的施工线。
- 消除同一信息在多个区域重复出现的问题。
- 把“结构起点”明确表达为“聚焦结构的起点”，减少“为什么不是最左边”的误解。
- 隐藏 `p7` 这类内部实现编号，不把系统内部锚点直接暴露给用户。
- 把“聚焦起点 / 最后确认点 / 进行中点 / 当前段”四类角色彻底区分，避免把历史确认点误叫成“当前”。
- 让每个 badge / 标签只承担一种职责。
- 默认用户界面只使用中文，不再暴露英文技术字段。
- 让补充卡片具备明确层级，做到先看主结论，再看条件和后果。
- 对所有级别的起点增加“结构可解释性”约束，起点若无法支撑当前标准结构本身，就不得强行标成标准结构起点。

## 非目标

- 不修改结构识别算法。
- 不修改 `interpretation` 的总体语义模型。
- 不在本次引入复杂的 hover 联动或点击联动。
- 不在本次重做整页风格系统，只清理当前结构面板与拓扑图的视觉表达。

## 问题归因

### 1. 图层冲突

当前图上同时存在：

- 价格标签
- 点编号
- 起点 / 当前贴纸
- live 终点编号

它们都围绕同一个点位摆放，导致局部区域过密，价格信息被压住。

### 2. `live` 的视觉语言过重

`live` 现在同时拥有：

- 明亮外圈
- “当前”文字贴纸
- 虚线延长段
- 末端编号

这让用户第一眼看到的不是结构走势，而是一个风格不协调的强调元素。

### 3. 信息重复

当前页面至少三处在重复表达同一组信息：

- 顶部 badge
- “识别为 X，趋势 Y”正文
- 图下四宫格摘要

用户阅读时会感觉内容很多，但新增认知很少。

### 4. 文案没有区分“聚焦起点”和“整段走势左端”

对峰值切片或复杂结构来说，当前展示的是“本轮分析聚焦结构的起点”，不是“整张图最左边的第一笔”。

UI 如果仍写成“结构起点”，但不说明这是聚焦结构视角，就容易让用户误判。

### 5. 内部编号泄漏

`p7` 适合内部 explainability / render payload 使用，不适合作为面向用户的主展示编号。

用户可理解的是：

- `a1 / c1 / d3` 这类标准结构编号
- 或“聚焦起点 / 最后确认点 / 当前段”这类角色化文案

### 6. “当前”语义错位

当前图上实际混用了三种不同概念：

- `聚焦起点`
  当前被分析结构切片从哪里开始算
- `阶段锚点`
  旧 `prediction.current_stage` 对应的历史确认点
- `最新点`
  也就是最新价格点，若尚未确认，属于进行中点

现有 UI 把 `prediction.current_stage` 对应点直接叫成“当前”，会导致明显误导。

以用户指出的例子为准：

- `181.9` 是聚焦结构起点
- `170.4` 最多只能算旧的阶段锚点
- `150.8` 才是最新价格点，也就是进行中点

因此，本次要明确：

- “当前”一词不再用于历史确认点
- 历史点如果需要展示，只能叫“最后确认点”或“阶段锚点”
- 最新未确认点统一叫“进行中点”

### 7. 用户界面泄漏技术字段

当前补充卡片右上角仍出现：

- `SCENARIO_PATHS`
- `PREDICTION`
- `LEFT_STRUCTURE_WARNING`

这些字段属于后端 key，不属于用户阅读层。

默认 UI 必须是中文分析界面，而不是“字段映射界面”。

### 8. 起点算法的结构可解释性不足

当前部分级别存在“算法能算出起点，但该起点无法由当前结构本身自洽支撑”的问题。

这在 `B` 结构上尤其明显，因为 `B` 的关键不是某一个局部低点，而是：

- 第一平台
- 平台间跃迁
- 第二平台

如果从某个点开始，往右不能自然读出这三层节奏，那么这个起点在产品上就是不合格的。

关键点不是“用户肉眼太弱”，而是：

- 既然系统已经识别为标准结构
- 那么这个结构的起点就必须由该结构自身推导出来
- 不能为了凑 `b1 / c1 / a1` 而随意指定一个点

## 总体方案

本次采用“去贴纸、降噪声、强分工”的方案。

### 一句话概括

- 图上只保留走势、价格、少量编号和轻量高亮。
- 结构语义主要在图外摘要区表达。
- badge 不再混装多个概念。
- 补充卡片回到中文、克制、有层级的分析面板风格。
- 起点展示从“算法直接外露”升级为“由结构本身推导、且经过解释性筛选后的聚焦起点”。

## 角色语义规则

本次新增一层强约束，统一图上和图下的角色定义。

### 1. 聚焦起点

- 指 `focus_structure.start_anchor`
- 表示“当前分析聚焦结构从哪里开始算”
- 它不是整张图最左侧点
- 它也不是“当前点”

### 2. 最后确认点

- 指当前进入进行中尾段之前，最后一个已经确认的拐点
- 例如 `164.6`
- 它是当前段的起点
- 若要在图上强调，可以用轻量编号或次级说明表达

### 3. 进行中点

- 指最新价格点
- 如果该点尚未形成正式确认拐点，则它就是进行中点
- 例如 `150.8`
- UI 文案统一使用“进行中”，不再直接向用户展示 `live`

### 4. 当前段

- 指“最后确认点 → 进行中点”这段
- 例如 `164.6 → 150.8`
- 它才是当前真正正在走的那一段

### 5. 阶段锚点

- 旧 `prediction.current_stage` 对应点如果不是最新点，只能作为“阶段锚点”存在
- 它不能再承担“当前点”的 UI 语义
- 默认情况下，页面不需要显式展示这个词
- 如果要保留，只能放在补充说明里，不能放到主高亮位置

### 6. UI 用词强约束

- 禁止把 `prediction.current_stage` 对应历史点直接标成“当前”
- 禁止在默认 UI 中直接展示 `live`
- 禁止在默认 UI 中直接展示英文技术字段，如 `SCENARIO_PATHS`、`PREDICTION`、`LEFT_STRUCTURE_WARNING`
- 默认用户文案统一为：
  - `聚焦起点`
  - `最后确认点`
  - `进行中点`
  - `当前段`

## 视觉与交互规则

### 1. 点位高亮规则

#### 聚焦起点

- 仍然高亮，但改为“琥珀色外环”
- 不再在点上方额外挂“起点”贴纸
- 若存在标准编号（如 `c1`），保留编号
- 若不存在标准编号，不强行显示内部锚点号

#### 进行中点

- 改为“青色细外环 + 正常点心”
- 不再显示“当前”贴纸
- 不再显示 `live` 英文标记
- 若需要提示状态，仅在图外使用“进行中”

#### 最后确认点

- 如需强调，只使用轻量编号或小范围视觉强调
- 不再给它“当前”主视觉待遇

### 2. 进行中尾段规则

- 当前进行中的尾段保留虚线语义
- 但线宽要比当前实现更细
- 颜色从高饱和亮绿改为低饱和、半透明的冷色
- 末端点使用轻量强调，不再做过重描边

目标效果：

- 用户能看出“这段还在形成中”
- 但不会抢走整张图的主视觉注意力

### 3. 图上文本规则

- 价格标签优先级最高，不能再被“起点 / 当前”文案遮挡
- 点编号只保留必要编号：
  - 标准结构：保留 `a1 / c2 / c4 / c6` 这类关键点
  - 复杂结构：不展示 `p7 / p15` 这类内部点号
- 图上如需表达进行中状态，使用中文“进行中”放在图外，不在点位旁叠英文 `live`
- 若点位过密，优先保价格标签，其次保关键编号，再次保其他辅助文字

### 4. badge 分工规则

拓扑标题区的 badge 固定拆成以下几类：

- `背景`
- `原型`
- `成熟度`
- `当前段`
- `拐点数`

规则：

- 一个 badge 只放一个概念
- 不允许把“原型 + 成熟度 + 图标”塞进同一个 badge
- 峰值或切片类辅助标记，如确有必要，作为独立小徽标出现，不与主文案混写
- 禁止在 badge 中同时出现“点编号 + 价格 + 状态”三类信息

### 5. 补充卡片中文化规则

以下技术字段名不再出现在默认 UI：

- `SCENARIO_PATHS`
- `PREDICTION`
- `LEFT_STRUCTURE_WARNING`
- `JUDGMENT_CRITERIA`

统一替换为纯中文标题：

- `改判路径`
- `预测提示`
- `左侧结构提醒`
- `判定标准`

若右上角仍保留辅助角标，也只能使用中文，不再显示技术 key。

### 6. 摘要卡规则

图下摘要卡固定改为：

1. `聚焦起点`
2. `最后确认点`
3. `进行中点`
4. `下一确认`

说明：

- 原“结构起点”统一改名为“聚焦起点”
- 用词上明确它是“当前分析焦点的起点”
- `最后确认点` 和 `进行中点` 分开显示，不再把历史点误当成当前
- `参考原点` 不再占主摘要卡位，改为放在“聚焦起点”的次级说明里
- 这样可以避免一个卡片里同时混“点号 / 价格 / 日期 / 参考原点 / 当前状态”多层信息

### 7. 补充卡片层级规则

每一张补充卡片都必须具备三层结构：

1. 主结论
2. 触发条件 / 关键位置
3. 后果 / 操作含义

以“改判路径”为例：

- 第一行：`上破上沿`
- 第二行：`有效突破 171.99`
- 第三行：`平台向上突破，可能升级为推进结构`

要求：

- 第一行字号最大、字重最高
- 第二行次级强调
- 第三行作为解释说明，字重最低
- 不允许三层信息全部使用同一字号、同一颜色、同一灰度

### 8. 风险卡视觉规则

“左侧结构提醒”不得再使用大面积高饱和粉红/红底整块铺满的做法。

新规则：

- 使用浅色语义底，例如轻微红/橙 tint
- 红色只用于边框、标题、风险 icon 或关键警示词
- 正文保持正常阅读对比度
- 整体视觉必须与普通信息卡属于同一设计体系，不应像独立报警弹窗

### 9. 正文去重规则

删除或下线这类重复正文：

- `识别为C单平台式，震荡趋势`
- `识别为延伸A类，上涨趋势`

原因：

- 这些信息已经被 badge 与摘要卡覆盖
- 正文应留给真正新增的信息，而不是重复摘要

### 10. `p7 / p15` 之类编号的展示规则

#### 标准结构

- 允许显示 `a1 / b3 / c5 / d4`

#### 复杂 / 未完成结构

- 默认不显示 `p7 / p15`
- 若必须表达该点的重要性，使用角色化文案：
  - `聚焦起点`
  - `最后确认点`
  - `进行中点`

即：

- `p7` 的来源是内部通用点号，即 `point 7`
- 它只用于后端 explainability / render payload / 调试定位
- 面向用户的默认文案不直接暴露 `p7`

### 11. 起点算法的结构可解释性规则

起点选择新增三重约束：

1. 结构完整性
   - 从该点开始，向右必须能支撑当前结构原型的基本轮廓
2. 图形可读性
   - 图形节奏能顺着该点自然展开，而不是只能依赖内部编号解释
3. 级别一致性
   - 该起点不能与相邻级别的主要背景明显冲突

并新增一条总原则：

- 起点必须是“当前结构的第一可解释锚点”
- 不是“后端为了映射标准编号而随手选出的一个点”

#### B 结构的特别规则

若前端展示为 `B双平台式 / B双平台原型`，则起点必须满足：

- 从该点往右，能读出第一平台的开始
- 中间存在可识别的平台间跃迁
- 后续能看出第二平台或第二平台候选

如果这三条有一条不满足，则：

- 不得硬标成 `b1`
- 不得在主 UI 里强行展示“这是 B 结构起点”
- 应改为：
  - 下调为 `B原型候选`
  - 或回退为 `复杂结构 / 未完成结构`
  - 或重新选择更有解释力的聚焦起点

进一步说：

- 如果系统已经宣称“这是 B 结构”
- 那么系统就必须同时给出一个由 B 结构本身推导出的、可解释的起点
- 若连起点都无法稳定解释，这不是用户的问题，而是识别和映射规则还不够好

这条规则适用于所有级别，不单独区分 15 分钟、30 分钟、60 分钟或日线。

## 数据映射规则

### 1. 起点文案

- 若 `focus_structure.start_anchor.point_id` 属于标准结构编号，则摘要卡显示：
  - `c1 @ 181.92`
- 若属于内部锚点，如 `p7`，摘要卡显示：
  - `181.92`
  - 不显示 `p7`

### 2. 最后确认点文案

- 显示最后一个已确认拐点价格
- 如存在标准编号，可显示为：
  - `c5 @ 164.60`
- 若不存在标准编号，则只显示价格：
  - `164.60`

### 3. 进行中点文案

- 显示最新价格点
- 默认文案为：
  - `150.80`
  - 次级说明：`进行中`
- 不显示 `live`

### 4. 参考原点文案

不再占主摘要卡位，只作为聚焦起点卡的次级说明显示为：

- `2026-02-25 @ 156.48`

不再加“参考原点”前缀进卡片正文。

### 5. 当前段文案

保持：

- `164.6 → 150.8`
- 第二行再显示：
  - `下行进行中`

不要合并成一个超长 badge。

### 6. 下一确认文案

拆成两层：

- 第一行：`等待 c6 拐点`
- 第二行：`突破点`

若 `next_confirmation` 无标准编号，则写成：

- `等待下一确认`
- 第二行保留触发类型，例如 `方向选择` / `突破确认`

### 7. 标准结构起点映射约束

标准结构起点不是“编号映射产物”，而是“结构识别结果的一部分”。

也就是说：

- 先有可解释的结构起点
- 再有 `a1 / b1 / c1 / d1` 这类标准编号
- 不能反过来为了显示标准编号，倒推出一个并不成立的起点

若起点经过解释性校验后仍不足以稳定映射为标准结构起点，则：

- 摘要卡不显示 `a1 / b1 / c1 / d1 @ 价格`
- 改为只显示：
  - `聚焦起点`
  - `价格`

- 标准编号是“解释成立后的结果”
- 不是“后端算出来就必须展示”的强制结果

## 版式规则

### 1. 顶部区域

从当前“多枚挤在一起的 badge”改成两排、低拥挤度布局：

- 第一排：背景 / 原型 / 成熟度
- 第二排：当前段 / 拐点数

### 2. 图下摘要区

- 保持四列桌面布局
- 每个卡片只展示一个主结论和一条辅助信息
- 卡片高度尽量接近，避免某一张卡因堆叠信息显著变高

### 3. 补充卡片版式

- “改判路径”中的每条路径要做成清晰的二级卡片
- “预测提示”要有明确主句、阶段信息、操作提示层级
- “左侧结构提醒”要回到正常信息卡体系，不再用大面积重色块压住整页气质

### 4. 图内留白

- 上边距要给价格标签和锚点外环留足空间
- 进行中尾段末端不能贴近右边框
- 若当前点在上方密集区，优先自动错开编号与价格标签

## 验收标准

### 视觉验收

- 图上不再出现“起点 / 当前”贴纸遮挡价格标签
- 进行中尾段看起来更轻，不再显得突兀
- badge 的每一枚都只表达一类信息
- 上下重复文案明显减少
- 默认 UI 不再出现英文技术字段
- 改判路径 / 预测提示 / 左侧结构提醒 都具备明确层级
- 风险提醒卡与全页风格协调，不再像独立报警模块

### 语义验收

- 用户能理解“聚焦起点”不是“整张图最左点”
- 复杂结构默认不再出现 `p7 / p15`
- 用户不会再把历史确认点误认成“当前点”
- 默认 UI 不再出现英文 `live`
- 标准结构仍保留 `a1 / c1 / d4` 这类有意义的编号
- 若某个级别的起点无法支撑用户直观看懂结构，则 UI 不得强行展示标准编号

### 具体案例验收

以用户给出的两类案例为准：

#### C 平台案例

- 图上 `181.9` 可以作为“聚焦起点”高亮
- 图下显示 `聚焦起点 181.92`
- 图下单独显示 `最后确认点 164.60`
- 图下单独显示 `进行中点 150.80`
- `当前段` 表达为 `164.6 → 150.8，下行进行中`
- 不再强制把 `c1 @ 181.92` 与“参考原点”塞进同一卡片
- `进行中` 尾段明显更轻、更协调

#### 复杂 / 延伸 A 类案例

- 图下不再显示 `p7 @ 181.92`
- 改为仅显示 `聚焦起点 181.92`
- 若旧 `prediction.current_stage` 对应点是 `170.4`，它不能再显示成“当前”
- 最新点如为 `150.8`，则“进行中点”必须落在 `150.8`
- 若用户需要内部编号，应通过开发态调试信息或后续 hover 解释查看，而非默认主展示

#### B 结构起点案例

- 若从当前聚焦起点一路往右，仍然无法自然读出双平台节奏，则：
  - 不得强行显示 `b1`
  - 不得用主 UI 宣称“这是 B 双平台式起点”
- 需要重新选择更有解释力的起点，或下调为 `B原型候选 / 复杂结构`

## 回归验证要求

任何涉及以下内容的改动：

- 起点选择
- 编号映射
- 当前段 / 进行中点语义
- 结构拓扑 UI 呈现

都必须做多级别回归验证，不能只看单一级别。

最低回归级别：

- `weekly`
- `daily`
- `hour60`
- `hour30`
- `hour15`

至少验证：

1. 一个平台型案例
2. 一个趋势推进型案例
3. 一个复杂 / 未完成结构案例

若某个改动只在一个级别看起来变好了，但在其他级别让起点或当前段更难解释，则该改动不能视为通过。
