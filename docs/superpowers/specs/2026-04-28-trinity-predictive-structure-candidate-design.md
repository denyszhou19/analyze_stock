# 三位一体前瞻结构候选与时空联动设计

## 0. 背景

当前系统对结构的主判断仍然偏向“回看分类”：

- 先用窗口内已有笔和宏观组件回看它更像 A / B / C / D 的哪一种完整结构
- 再把这个回看结果映射到三位一体时空和执行层

这会带来三个问题：

1. 结构标签偏慢  
   如果必须等标准 A / B / C / D 走得比较完整才切换主标签，实际交易会错过更前面的预判阶段。

2. 旧整理主语压住新推进主语  
   当右侧最新走势已经明显转成推进，但历史上仍可解释为 B / C 整理遗留时，系统会过度尊重旧整理背景，导致主标签切得太慢。

3. 复杂结构滥用  
   当前窗口稍复杂就容易落到“复杂结构 / 延伸结构”，但交易上真正需要的是：右侧最新走势最可能接下来演化成什么，并据此结合时空做准备。

本次设计要把结构层从“回看分类器”改成“前瞻候选器”。

## 1. 设计结论

新的主规则如下：

> 时空先限定当前允许优先关注的结构候选集合；结构层再根据最新走势主语，从集合内选出主候选和次候选；交易层按主候选而不是按已完成结构执行映射。

这意味着：

- 结构层的核心任务不再是回答“已经完整走成了什么”
- 而是回答“当前走势最可能正在演化成什么”

在这套新规则里：

- `A候选` 可以在推进主语占优时优先切出，不必等待标准 A 完整走完
- `B / C` 不再因为旧整理遗留而自动压住新的推进判断
- `A候选` 的切换必须经过防抖确认，不能因为 1-2 根局部爆发 K 线立即抢占主标签
- `D候选` 不作为默认入口，而只作为其他候选都不支持时的最低保真降级出口；极端动能型 D 单独作为系统级异常中断处理
- 交易层在主候选之外，还必须经过“方向锁”检查，避免逆大级别均线压力/支撑过早给出试探动作

## 2. 目标与非目标

### 2.1 目标

1. 把结构判断从“已完成分类”改成“前瞻候选选择”。
2. 让时空先决定“当前允许优先关注哪些结构候选”。
3. 让推进主语占优时，允许 `A候选` 压过旧的 `B / C` 遗留解释。
4. 让 `复杂结构` 不再成为终点，而是触发“右侧最低保真候选”尝试。
5. 明确 `D候选` 的角色：降级出口，而不是默认第一候选。
6. 让交易层基于“主候选 × 候选阶段 × 时空许可”给出动作建议。
7. 为主语切换增加防抖/迟滞机制，降低 A / B / C 之间的状态横跳。
8. 在交易层加入“方向锁”，限制逆 MA55 / MA233 关键压制或支撑的试探动作。
9. 为候选切换补充结构化触发信号字段，避免完全依赖自然语言原因。

### 2.2 非目标

1. 不在本阶段重写所有原始笔识别与聚类算法。
2. 不在本阶段重做 UI 布局。
3. 不在本阶段引入连续评分模型替代 A / B / C / D 候选。
4. 不在本阶段取消原始全局结构记录；原始结构仍保留供解释与回溯使用。
5. 不在本阶段把 `D异常` 直接扩展成独立右侧跟随策略；本阶段只把它定义为风险中断机制。

## 3. 新的判定框架

### 3.1 三层职责

新的结构-时空-交易链分成三层：

1. 时空层  
   回答：当前父级状态下，子级优先允许哪些结构候选进入操作视野。

2. 结构层  
   回答：基于最新走势主语，当前最可能正在演化成什么结构；给出主候选和次候选。

3. 交易层  
   回答：若按主候选代入时空表，当前最多可以做到什么程度，是等待、轻仓试探还是标准执行。

### 3.2 核心原则

1. **先限范围，再选候选**  
   时空层先给结构候选集合，结构层不得跳出集合直接给交易候选。

2. **先看主语，不先看旧标签**  
   结构层先判“推进 / 整理 / 反抽 / 分歧混合”谁占优，再决定当前候选。

3. **候选优先于完成**  
   结构层可以先给 `A候选 / B候选 / C候选 / D候选`，不必等标准结构完整成立。

4. **复杂结构不是终点**  
   如果全局结构复杂，但右侧最新走势已有最小可解释性，必须继续尝试输出右侧候选。

5. **D 不是默认入口**  
   D 只在更高优先级候选都不支持时，作为最低保真降级解释。

6. **主语切换必须防抖**
   单次局部爆发、1-2 根大阳/大阴或单个局部拐点，不足以立即切换主候选。

7. **交易执行必须经过方向锁**
   候选结构解决“像什么”，但不能越过 MA55 / MA233 关键压制或支撑直接升级执行强度。

8. **D 异常与 D 降级要分开**
   一类 D 只是最低保真结构解释；另一类 D 是极端动能中断，只能触发风控优先。

### 3.3 页面显示归属

前瞻候选合同会同时影响 `综合判断`、`交易周期总线`、`周期详情`，但三者不能各自重复讲同一套话。

显示归属固定如下：

1. `AnalysisSummaryPanel`
   - 只负责页级综合结论、页级阻塞、页级风险提醒
   - 可以引用 `primary_candidate`，但只用来回答“当前全页最重要的结论是什么”
   - 不展开组合级动作细节，不复述周期详情证据

2. `TradingCycleBus`
   - 只负责组合级动作、组合级约束、组合级风险
   - `primary_candidate / candidate stage / direction_lock` 在这里用于回答“这条组合现在最多能做到什么程度”
   - 不复述整页总览，也不在这里展开单级别结构证据

3. `AnalysisPeriodDetails`
   - 只负责该级别结构证据、父级约束、下一确认与失效边界
   - 可以引用 `primary_candidate / dominant_narrative / narrative_switch`
   - 但不能再次输出“当前动作 / 仓位 / 交易指令”

一句话：

> `综合判断` 讲全页结论，`交易总线` 讲组合动作，`周期详情` 讲结构证据；三层都可以引用同一合同，但职责不能重叠。

## 4. 时空层口径

### 4.1 时空层输出的不是唯一结构，而是候选集合

例如：

- 父级 `极强`
  - 子级上涨结构：优先允许 `A / B`
  - 子级下跌结构：默认不优先

- 父级 `中偏强`
  - 子级优先允许 `C`
  - 如果右侧走势转为推进，可以允许 `A候选` 进入观察，但执行强度要降级

- 父级 `极弱`
  - 子级下跌结构：优先允许 `A / B`
  - 子级上涨结构：默认只允许反抽观察，不优先给交易候选

因此，时空层的职责是：

- 给出 `allowed_candidates`
- 给出 `blocked_candidates`
- 给出 `degraded_candidates`

而不是直接输出“当前就是 A / B / C / D”。

### 4.2 结构候选与交易候选要分开

某个候选结构在结构层可以成立为“解释候选”，但不一定进入交易层。

例如：

- 右侧最新走势可以被解释为 `D候选`
- 但若父级时空当前只允许 `A / B`
- 那么 `D候选` 只能保留为结构层降级解释，不进入交易候选

一句话：

> 结构候选说明“它像什么”；交易候选说明“它能不能按这个去做”。

## 5. 结构层口径

### 5.1 先判最新走势主语

结构层首先要判当前右侧主语，而不是先看旧结构标签。

主语分为四类：

1. `推进主导`
2. `整理主导`
3. `反抽主导`
4. `分歧混合`

解释如下：

- `推进主导`：高低点沿同一方向连续推进，右侧主阅读是“正在走一段”
- `整理主导`：价格围绕相对稳定核心区反复往返，主阅读是“震荡整理”
- `反抽主导`：更像对既有单边走势的修复或反向拉回
- `分歧混合`：推进与整理都不够占优，或不同解释都成立

### 5.2 候选优先顺序

结构层根据主语和时空允许范围选主候选。

#### 推进主语占优

优先顺序：

1. `A候选`
2. `B候选`
3. `C候选`
4. `D候选（仅作降级）`

说明：

- 若时空允许 `A / B`，且当前推进主语明显占优，则优先切到 `A候选`
- 即使旧整理背景仍存在，也不能继续让 `B / C` 主导当前标签

#### 整理主语占优

优先顺序：

1. `B候选`
2. `C候选`
3. `A候选`
4. `D候选（仅作降级）`

#### 反抽主语占优

优先顺序：

1. 时空允许集合内、最符合反抽主语的 `A / B / C候选`
2. 次优允许候选
3. `D候选（仅作降级）`

说明：

- 反抽主语占优，不等于直接把 `D候选` 提升为默认第一候选
- 仍然应先检查时空允许集合内，是否已有更高优先级的 `A / B / C` 反抽解释
- 只有这些解释都不支持时，才允许降级到 `D候选`

#### 分歧混合

允许输出：

- `A/B 分歧`
- `B/C 分歧`
- `A/C 分歧`

而不是被迫硬压成单一标签。

### 5.3 A 候选切换规则

新增强规则：

> 只要推进主语占优，且 A 在时空允许候选集合内，就优先切到 `A候选`。

这条规则用于修正当前系统“旧整理主语压住新推进主语”的问题。

其含义是：

- `A候选` 不必等待标准 A 完整成立
- 只要当前右侧走势已经主要表现为推进，就允许 A 成为主候选

但是，这条规则要增加防抖约束：

#### 5.3.1 防抖（Debounce）与迟滞区间

推进主语占优，不等于立刻切换到 `A候选主导`。

为了防止中大级别 C 震荡中的假突破、诱多大阳、诱空大阴导致状态横跳，必须增加切换门槛：

1. **单次局部爆发不足以切换**
   - 1-2 根大阳/大阴
   - 单个局部破高/破低
   - 单个拐点的突刺
   都只能视为“推进尝试”，不能直接让 `A候选` 抢占主标签。

2. **必须通过结构化切换门槛**
   推进主语从“观察到”升级为“可主导”，至少满足以下任一条件：
   - `1 个硬触发`
   - 或 `2 个软触发且无明显反向阻断`

3. **未过门槛时保留分歧区**
   若推进主语已经冒头，但未通过切换门槛，则输出：
   - `A/B 分歧`
   - 或 `A/C 分歧`
   而不是立刻压成单一 `A候选`

#### 5.3.2 结构化触发信号

为避免完全依赖自然语言原因，切换门槛应结构化记录触发信号。

建议信号分层如下：

- 硬触发（示例）
  - `macd_zero_axis_break`
  - `macd_strength_new_high`
  - `ma55_effective_break`
  - `ma233_effective_break`
  - `volume_breakout_confirmed`
  - `parent_release_confirmed`

- 软触发（示例）
  - `lower_high_lower_low_sequence`
  - `higher_high_higher_low_sequence`
  - `platform_edge_reclaim`
  - `current_leg_extension`

- 阻断信号（示例）
  - `ma55_direct_resistance`
  - `ma233_direct_resistance`
  - `parent_not_released`
  - `volume_not_confirmed`

只有在硬触发或软触发满足门槛，且阻断信号未主导时，才允许 `A候选` 从“分歧/观察”升级成主候选。

### 5.4 复杂结构的处理

`复杂结构` 不再直接作为第一页主结论，而是触发右侧候选重试。

流程：

1. 先保留原始全局结构为 `complex / extended`
2. 再只看右侧最新走势
3. 按时空允许范围重新尝试输出主候选
4. 如果高优先级候选都不支持，再尝试最低保真降级候选

因此，以后页面上允许同时存在：

- `原始全局结构：复杂结构`
- `当前主候选：A候选`

这两者不冲突，职责也不同。

### 5.5 D 候选的角色

D 的正确位置是：

- 不是默认第一候选
- 不是复杂结构的自动替代品
- 而是高优先级候选不支持时的最低保真降级出口

但 D 需要进一步拆成两类：

#### 5.5.1 D 降级解释

用于：

- A / B / C 高优先级候选都不支持
- 右侧最新走势仍有最小单边推进解释
- 结构层需要给出一个最低保真候选，而不直接停在 `复杂结构`

这类 D：

- 只承担结构解释职责
- 默认不升级为主动交易候选
- 交易层一般落在 `observe_only / wait_confirmation`

#### 5.5.2 D 异常中断

用于：

- V 反级别的极端快速反转
- 明显的动能失控、消息驱动脱框波动
- 已经超出正常 A / B / C 候选切换逻辑的极端盘面

这类 D：

- 不是普通结构候选
- 也不是“保真度最低的普通解释”
- 而是 **系统级异常中断（exception interrupt）**

其交易含义不是“正常试探”，而是：

- 强制重新评估
- 强制风控优先
- 必要时直接剥夺 `light_probe`

本阶段只把它定义为风险中断，不把它扩展成独立右侧跟随交易策略。

只有满足下面条件时，才允许输出 `D候选`：

1. 时空允许范围内的更高优先级候选都不支持
2. 右侧最新走势已经有最小单边推进解释
3. 当前主语不是稳定整理主导

如果连 D 都解释不了，才继续保留 `复杂结构` 作为最终结构层结论。

## 6. 新合同建议

### 6.0 用户可见中文映射边界

`structure_prediction`、`direction_lock`、`exception_interrupt` 的原始字段名、`stage` 枚举、`trigger_signals` 枚举，只能作为内部合同存在。

用户可见区域必须遵守：

1. 不直接显示 `debouncing / strengthening / blocked / exception`
2. 不直接显示 `direction_lock / exception_interrupt / narrative_switch`
3. 不直接显示 `macd_zero_axis_break / parent_not_released` 这类信号枚举

这些字段进入页面、hover、AI 正文、AI 追问前，必须先经过统一中文映射。

### 6.1 原始结构与预测结构分离

继续保留原始结构，但新增预测结构字段。

### 6.2 候选阶段

`stage` 统一使用：

- `debouncing`
- `candidate`
- `strengthening`
- `standard_confirmed`
- `degraded`
- `blocked`
- `exception`

说明：

- `debouncing`：走势开始像某候选，但尚未通过主语切换门槛
- `candidate`：已进入该结构候选框架
- `strengthening`：候选正在增强，但未达标准确认
- `standard_confirmed`：标准结构成立
- `degraded`：仅保留为降级解释
- `blocked`：结构上可解释，但时空不允许作为交易候选
- `exception`：极端动能中断，不走常规候选执行映射

## 7. 交易层口径

### 7.1 交易建议基于主候选，不基于已完成结构

交易层不再问：

> 这是不是已经标准 A / B / C / D？

而是问：

> 若按当前主候选结构代入时空表，当前最多允许做到什么程度？

例如：

- 主候选 = `A候选`
- 候选阶段 = `candidate`
- 父级时空允许 `A / B`

则交易层可以输出：

- `等待确认`
- `轻仓试探`
- `条件边界交易`

但不能直接升级为：

- `标准节点交易`

此外，还要经过方向锁检查：

- 若当前候选方向正顶在 `MA55 / MA233` 强压制下
- 或正打在关键支撑反向破位附近
- 那么即使候选阶段允许 `light_probe`，也必须被降级

因此，结构候选只回答“像什么”，交易层还要回答“当前能不能朝这个方向出手”。

### 7.2 方向锁（Direction Lock）

新增方向锁参数，作为交易层的强制二次门控：

- `released`
- `mixed`
- `locked`

其职责是检查：

1. 当前主候选方向是否正迎着 `MA55` 压制
2. 当前主候选方向是否正迎着 `MA233` 压制
3. 当前候选是否虽然成立，但上方/下方存在紧邻关键引力线

当方向锁为 `locked` 时：

- `light_probe` 必须降为 `wait_confirmation`
- `conditional_boundary_trade` 必须降为 `observe_only`
- `standard_node_trade` 不得放行

### 7.3 候选阶段与执行强度

建议映射如下：

- `debouncing` -> `wait_confirmation / observe_only`
- `candidate` -> `wait_confirmation / light_probe`
- `strengthening` -> `light_probe / conditional_boundary_trade`
- `standard_confirmed` -> `standard_node_trade`
- `degraded` -> `observe_only`
- `blocked` -> `no_trade`
- `exception` -> `risk_control_first / no_trade`

因此：

> `A候选` 允许进入 A 的交易框架，但执行强度低于 `标准A`。

若方向锁为 `locked`，则以上映射仍需再向下强制降级。

### 7.4 周期详情证据优先级

周期详情虽然要消费新合同，但必须继续遵守“先结论、再摘要、再证据”的顺序，不能变成字段堆砌。

证据优先级固定如下：

1. 首屏主证据
   - `结构匹配状态`
   - `当前段`
   - `下一确认`

2. 次级支撑证据
   - `均线背景`
   - `结构方向`
   - `均线关键位`

3. 拓扑与结构说明
   - 结构图
   - 原始结构解释
   - 降级说明

也就是说，`均线背景 / 结构方向 / 均线关键位` 是帮助理解主证据的支撑层，不应和 `结构匹配状态 / 当前段 / 下一确认` 争抢首屏主语。

## 8. 300033 30分钟案例解释

以 `300033` 30分钟为例：

- 当前原始全局结构可落在 `延伸C类`
- 峰值切片后的右侧可能还能被旧算法解释为 `B双平台式`
- 但如果右侧最新走势已经表现为明显下行推进，且时空允许集合包含 `A / B`

那么新系统应当允许输出：

- `主候选：A候选`
- `次候选：B候选`
- `主语：推进主导`

而不是继续让 `B候选` 固定主导当前结构标签。

## 9. 验收标准

1. 结构层可以同时保留：
   - 原始全局结构
   - 当前主候选
   - 次候选

2. 推进主语占优时，只要 A 在时空允许集合内，必须允许 `A候选` 成为主候选。

3. 推进主语的切换不能因单次局部爆发直接完成，必须通过结构化切换门槛；未过门槛时保留分歧状态。

4. `D候选` 不能作为默认第一候选；`D异常` 必须单独进入风险中断通道。

5. `复杂结构` 不能直接成为交易解释终点，必须先尝试右侧最低保真候选。

6. 交易层必须按“主候选 × 候选阶段 × 时空许可 × 方向锁”给建议，不再直接绑定“已完成结构类型”。

7. 合同必须提供结构化触发信号，不能只靠自然语言 `reason` 支撑主语切换。

## 10. 实施顺序建议

1. 先在后端新增 `structure_prediction` 合同字段，不动旧字段。
2. 再实现“时空允许候选集合”输出。
3. 再实现“主语识别 + 主候选 / 次候选”选择。
4. 再把交易资格从“已完成结构”切到“主候选结构”。
5. 最后更新前端展示文案，把“原始结构”和“当前主候选”分开显示。
